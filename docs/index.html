选路由额度说话

同一个模型可能有五六家在供。候选按「账号池剩余额度之和 × 速度 × 可靠性」排序，先出额度最多的那家；这家烧光就顺延下一家 —— 你看到的永远是结果，不是过程。

loomy 2 329selected
raccoon 1 020standby
traecn 232standby
workbuddy 100standby
catpaw —off

一层层往下换，不用你管

  1. 渠道内某个账号额度耗尽 → 自动换号，本次请求重试一次
  2. 整家渠道烧光 → 顺延下一家候选
  3. 连续失败 → 熔断，退避 30s 起、翻倍封顶 30min
  4. 到点 → 半开试探，一次机会，成了就复活
  5. 鉴权失败 → 不换号，凭据问题换号只会掩盖真因

除了转发，还替你把运维做完

签到、额度刷新、目录保鲜、日志留底都是常驻的。它们不出现在请求路径上，但少了任何一个，池子都会慢慢变脏。

登录与多账号池

按渠道自己的方式登录（扫码 / 设备码 / 短信），一个渠道挂多个账号，凭据与状态分别落盘。

自动签到与额度刷新

支持签到的渠道每天自动领；全渠道额度每 3 分钟并行重查一次，冷却到期自动放行。

请求日志与回放

每条模型请求落一条访问日志：耗时、首字、生成速率、缓存命中、选路快照，失败带错误码。

三种入站协议

OpenAI Chat Completions、Anthropic Messages、OpenAI Responses 同一套池子，模型名统一归一。

半开熔断

退避翻倍、封顶 30 分钟；到期只放行一次试探，避免多实例同时打醒一个垂死渠道。

Web 控制台

仪表盘、账号池、请求日志、API Keys 同端口托管；一键把本机客户端的模型清单指到网关。

在册渠道

能力以各渠道包声明的为准；计费类渠道有额度概念，订阅制渠道的模型按免费档显示。实时额度看 mx status。

四步跑起来

Node ≥ 22。本机单用户形态不需要数据库、不需要 Redis，也不需要先建 API key。不想碰命令行的话，直接用Windows 桌面版。

装依赖并构建

npm workspaces 一把装完，构建产出 CLI 单文件与 Web 控制台资源。

# 仓库根目录
npm install
npm run build

起网关

守护式启动，监听 127.0.0.1:4412；mx status 看池子。

node packages/cli/dist/cli.js start

登录渠道

按渠道自己的登录方式走一次，之后自动续期与签到。

node packages/cli/dist/cli.js login loomy

把客户端指过来

任何 OpenAI 兼容客户端；也可以让控制台「一键接入」改写本机配置。

node packages/cli/dist/cli.js web

OpenAI 兼容；模型填裸名，别的名字一律 400。

需要多设备共享又不想裸奔？设置里开启「要求 API key」，每个 key 可限定模型白名单与每分钟请求数。

Windows 桌面版

不想碰命令行就用安装包：双击装完，桌面一个快捷方式，剩下的它自己办。

安装包 NSIS 一键安装，装到 %LOCALAPPDATA%\Programs\modelmux-desktop
零依赖 不需要 Node.js / npm / CLI，也不需要 VC++ 运行时（CRT 静态链接）
启动 双击快捷方式自启网关并显示控制台；已有网关在跑就复用，不重复起实例
常驻 关窗收进托盘，网关继续在后台接请求；托盘菜单退出才真退
自愈 每 10 秒探一次 /health：网关断了换说明页，起来了自动载回控制台
窗口 1000×720，记住上次位置与尺寸；标题栏隐藏，顶栏即拖拽区

系统要求

Windows 10 1809+ / 11，x64。首次使用要在控制台逐渠道登录 —— 安装包不附带任何凭据。

先说清楚边界

这些不是缺陷，是刻意的取舍 —— 写出来是为了你在用它之前就知道。

只本机监听

网关只绑 127.0.0.1。要让别的机器用，请自行套反向代理并自行承担鉴权，不要直接暴露端口。

模型清单是固定的

对外只认家族表里的几个裸名。想让上游模型直接透传，这不是这个项目的目标。

额度是「最近一次账单」

选路依据是账本快照而非实时余额；账单刷新有周期，极端情况下会多撞一次上游限流。

单实例为主

多实例需要外置存储与协调层（可选的 PG + Redis 形态），默认不带 —— 单机够用就别加复杂度。
