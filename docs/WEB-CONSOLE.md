# Web 控制台（mx web）

`mx web` 把 React 管理看板挂在网关的**唯一端口**上（`http://127.0.0.1:4412/web/`，
控制台 API 在 `/web/api/*`），没有独立进程与独立端口。

## 设计系统（`packages/ui/src/index.css`）

视觉语言参照 **Codex / ChatGPT**：**纯近黑单色系**。顶部导航比内容区更深、浮层比内容区更浅，
层级只靠底色差与留白表达；**accent 就是白**（主按钮白底黑字、选中态白色高亮），
不用任何彩色品牌色；状态语义色保留但饱和度压低，只出现在「需要人看」的地方。

UI 的配色、层级与圆角**只在 `index.css` 的 `@theme` 里定义一次**，组件一律用令牌类，
不直接写 `gray-900` / `sky-500` 这类原始色 —— 换主题只改这一处。

| 组 | 令牌类 | 用途 |
| --- | --- | --- |
| 表面（四个深度层） | `bg-surface` `#171717` / `bg-canvas` `#212121` / `bg-raised` `#2f2f2f` / `bg-overlay` `#3a3a3a` | 顶部导航（最深）→ 内容区 → 卡片与输入盒 → 悬浮层与选中底 |
| 描边 | `border-line` `#383838` / `border-line-strong` `#4d4d4d` | 几乎不用；需要分块时才出现，且刻意看不清 |
| 文字 | `text-ink` `#ececec` / `text-ink-soft` `#b4b4b4` / `text-ink-faint` `#8e8e8e` | 主 / 次 / 弱 |
| 语义 | `brand` **`#ffffff`** / `free` / `warn` / `danger` | **accent = 白**：主按钮是白底黑字（`text-[#171717]`），不是彩色底 |

三个组件类与一处动效：

| 类 | 用途 |
| --- | --- |
| `.panel` | 唯一的容器形态（`rounded-2xl border border-line bg-raised`），仪表盘卡、渠道卡共用 |
| `.panel-title` | 面板标题（图标 + 文字，14px 常规字重 —— 不靠加粗靠留白） |
| `.pill` | 徽标（状态 / 计数）；**语义类按状态着色**（正常绿 / 冷却黄 / 异常·没钱红，底色 12% 透明），纯计数类用中性底 |
| `.nav-item` | 顶部标签导航项（纯文本 + 圆角 hover 底；选中态 `bg-raised`，不用彩色底） |
| `.live-dot` | 网关状态灯的呼吸动效（`prefers-reduced-motion` 下自动关闭） |

约定：

- 圆角只有两档：容器 `rounded-2xl`、行内元素 `rounded-lg`；主按钮 `rounded-full`。
- **单色系**：除状态语义色（免费/冷却/错误）与下一条的「还原」例外，不出现任何彩色；
  主操作按钮一律 `bg-brand text-[#171717]`（白底黑字）。
- **动作色例外**：一键接入里的「还原」用 `warn` 淡黄（`border-warn/45 bg-warn/10 text-warn`）。
  语义是「非破坏性撤销」（写回接入前备份、可反悔），用中性描边会被读成禁用态；
  这是 `warn` 唯一一处非状态用法，新增前先想清楚要不要再借这个色。
- 标题是**无衬线常规字重**（ChatGPT 的标题不靠加粗靠留白），不用衬线字体。
- 数字用等宽数位（`.tabular`），统计值变化时不抖动。
- 键盘可达：`:focus-visible` 有统一聚焦环（鼠标点击不显示）。
- 图标统一用 `lucide-react`，尺寸三档：12（小徽标）/ 14（行内）/ 16（面板标题）。
- **品牌 mark 是内联组件**（`components/BrandMark.tsx`，极简鲸鱼剪影 +
  分叉尾鳍 = 多条渠道，单色、16px 清晰），与 `assets/favicon.svg` 同形（白色）；
  颜色跟随 `className` 的 `text-*` 令牌（顶部导航用 `text-ink`）。

成功绿 / 失败红，选中只是叠一层淡底，与表格结果列同源；渠道 / 日期 / 每页统一走自绘 `Select`（原生 `<select>` 的弹层由操作系统绘制，深色主题下是亮色高亮块，与整套 UI 割裂），且**三个下拉都固定宽度** —— 基准取**稳定集**（渠道按全部在册渠道的最长名、日期按完整 `YYYY-MM-DD`），不随当前选项集增减变化，切换选项时按钮位置与宽度恒定；触发器文字**水平居中**（含「今天」），箭头固定在右；**不做关键词搜索**（渠道 + 日期 + 只看慢已覆盖真实排查路径，多一个输入框只会让人以为能搜正文——正文在弹窗里）+ 只看慢；**渠道 / 日期 / 每页 10/20/50 三个下拉在筛选栏右侧同排**（每页**持久记忆**：按最后一次选择显示，非法存储值回落 10）—— 分页设置属于筛选条件，放表尾会让人滚到底才发现能改；**「清除筛选」常驻**（无筛选时禁用而非隐藏）；**不显示「共 N 条」** —— 统计条的总数是未过滤窗口、命中数是筛选结果，两个「总数」同屏对不上只会让人怀疑计数坏了；筛选变化自动回第 1 页）、**表格 + 吸底分页条**（时间 `MM-DD HH:mm:ss`（**不显示年份**）/ 结果 / **渠道** / 模型（deepseek 裸名）/ 耗时 / 生成速度 / **缓存（恒 `—`：上游没有命中率字段，不自己算）** / tokens 入·出，**全表居中**（表头与数据同列中心线重合 —— 左对齐时表头两字与数据长串只在左沿相碰、中心差几十像素；展开箭头在列内居中；结果列的状态点与状态码分居结果文字两侧等宽列、结果文字落列正中（点与码宽度不等会让文字被挤偏）；末列 tokens 右内边距加大，数据不与表格右沿贴死）。表头与表体**垂直对齐统一 `align-top`**（表头用 UA 默认的 `middle` 会与数据行差约 3px）；分页条 sticky 跟随视口底部，**只放上一页 / 页码 / 下一页**）。点行**展开**元数据详情（request id 可复制、method+path、三段耗时、请求规模、错误码与说明、usage）。请求正文的抓取仍在做（[LOGGING.md](./LOGGING.md) §9），但**控制台不再提供上下文弹窗** —— 需要上下文时直接从 `~/.modelmux/logs/payload/` 读对应请求的正文。5 秒轮询，展开、翻页或弹窗打开时暂停 |

> 日志页对网关 `error` 状态**豁免骨架**：控制台与网关同进程，能读到 `ui_state` 就说明进程还活着、
> `/api/logs` 也就能用 —— 而排查异常恰恰最需要看日志。`down`（网关真不在）与状态查询失败时
> 日志同样拿不到，仍走骨架（见 `components/LayoutSingle.tsx`）。

### 为什么 base_url 放顶部导航

最高频的动作是**把 base_url 抄走**，所以它做成顶栏右侧的胶囊（紧挨网关状态、带复制按钮），
不再占首屏一块卡片：仪表盘首屏让给 KPI 与趋势。窗口收窄时它**最早收敛**（阈值与
掉档顺序见「响应式适配」），地址在账号池页与文档里也能查到。

### 为什么账号卡有最小宽度

单卡低于约 340px 时，中文账号名与额度条互相挤压（实测「塞西莉亚4412」被截断），
故轨道取 `minmax(min(340px, 100%), 1fr)`：**列数跟着容器走**（1400px 下 3 列），
`min(340px, 100%)` 是窄屏收口 —— 视口比 340px 还窄时不把容器顶出横向滚动。

### 账号卡的布局统一（默认 1 个账号位 + 单行扁平 + 折叠）

多账号、多状态容易把页面撑得参差。定稿的规则是「只露 1 个 + 卡底条恒渲染」：

1. **每卡默认只露 1 个账号** —— 生效账号恒排首位，所以露出的就是最该看的那行；
   **卡底条恒渲染**，四态各一句话：
   - 0 个账号 → 铺**一个空位行**占位 + 卡底「暂无账号」
   - 1 个账号 → 1 行 + 卡底「已展示全部」
   - N 个账号（折叠）→ 1 行 + 卡底可点条「展开剩余 N-1 个账号」
   - N 个账号（已展开）→ 全部铺开 + 卡底可点条「**收起**」——动作写在**左下角**
     （与「展开」同一位置，手不用在卡里左右找；收起放右下角是错位的）

   实测（1440 视口，真实数据 12 渠道）：**三种卡高全部 140px**，
   空池靠占位行与别的卡等高 —— 账号池是横向等高的卡片列，缺一行就整片参差。
   为什么不全铺开：渠道池动辄 4-6 个账号，铺满会把「同屏能看几个渠道」压到 1-2 个，
   而账号池页先要回答的是「这个渠道还能不能用」。
2. **卡头第二行（额度周期）固定两行高度**：渠道声明了 `quotaPeriod` 就照实显示
   （`line-clamp-2`，长文案占两行、短文案留白到两行；完整文案在额度详情浮层里读）。
   没声明的**不填任何占位文案**（`min-h-8` 撑住两行高度）—— 写「暂无签到」这类字样等于
   替没有签到能力的渠道（`capabilities.signin: false`）宣称一项它没有的功能，
   「没这项功能」与「今天没签」是两回事；详情浮层的「今日签到」行按能力位**整行不渲染**。
   账单查询失败时显式写「额度周期未知（账单查询失败）」—— 留空白会把「接口挂了」
   显示成「这个渠道没有周期」。
3. **展开态只推同列、账号恒一列**：卡片不跨列，也**不留白带** —— 列布局是「按列分发」
   （`lib/card-columns.ts`：`ResizeObserver` 量容器宽 → `columnCount` → 轮询分发），
   每列是独立纵向流，展开只把**同一列**下面的卡往下推，另两列位置完全不变。
   `col-span-full` 与 `grid items-start` 都不成立：前者展开就占满整行、把右侧卡挤到下一行；
   后者不跨列了，但行轨道高度仍按行内最高卡算，另两张下方留 135px 白带。
   展开后账号**一行一个竖向排开**（不铺两列）：两列会把每行压成半宽、账号名与进度条互相挤，
   读序也会变成「左右左右」。
4. **账号行恒定单行 44px（`h-11`）**：状态点 / 名称 / 状态 pill（正常、冷却、没钱…）
   / **额度进度条 + 百分比** / 操作，全部横向排开。
   剩余额度、今日消耗、今日 tokens、今日首次账单、**今日签到**、冷却倒计时、熔断连败、凭据失效原因
   **全部收进进度条的悬停面板**（行内只留「还剩几成」，一眼读完）。
   - 进度条口径：**今日首次账单**（`baseline.remain`）为 100%，当前 `remain` 占它的比例；
     0–100%，耗尽染红、<10% 染黄、其余绿。
   - **「今日签到」行**：值来自本地签到台账（`<root>/channels/<cid>/state/signin.json`，
     旧布局回落 `<root>/<cid>/`；不查上游 ——
     账号池页是 15 秒轮询，不该为一行状态去打各渠道的上游端点）。渠道声明
     `capabilities.signin = false`（如 workbuddyai 国际版）时**整行不渲染** —— 写「未签到」
     会被读成「今天还没签」，与「根本没这项功能」是两回事。按账号签到的渠道（`signin.perAccount`，
     当前只有 loomy）读**该账号自己的**记录；其余渠道的 `claim()` 只作用于生效凭证，
     台账是渠道级的，值里带「（渠道）」标注。
   - 面板：悬停 / 聚焦显示，点击可**固定**（触屏没有悬停），点外部或 Esc 关闭；
     portal 到 `document.body`（卡根节点 `overflow-hidden`，不 portal 会被卡底裁掉），
     实测自身尺寸后钳制在视口内、贴下缘自动翻到进度条上方。
   - 面板配色跟卡片层级走：`bg-overlay`（比卡片 `bg-raised` 高一档）+ `line-strong` 描边，
     不用近黑色 —— 近黑浮层在深色主题里像另一个应用。
5. **切换 / 删除默认隐藏**，鼠标移到该账号行才出现（`group-hover`）；
   `group-focus-within` 保证键盘可达，`pointer-coarse`（触屏）常显。
   删除走**确认弹窗**（见下文「不可逆操作」）。

### 模型清单（仪表盘内联，`pages/Dashboard.tsx`）

**为什么不再有独立的模型列表页**：对外模型只有家族表里几个名字，一页专门列表收益太低；
而「这个模型现在能不能用、快不快」是仪表盘首屏就该回答的问题，所以内联进仪表盘右列。

| 元素 | 形态 |
| --- | --- |
| 行内容 | 模型名（等宽，deepseek 裸名）+ **平均 TPS**（近 7 天成功请求均值，算不出显示 `-`）+ **输入模态图标**（`T` = 文本恒有；`+` 图片图标 = 支持图片） |
| 模态口径 | 同一模型的不同渠道能力不同（有的渠道只收文本、有的收图片），行内取**并集**—— 答的是「这个模型能不能收图」，与「候选渠道有哪些」同一层级；逐渠道能力看 `GET /web/api/state` 的 `models[].meta.inputModalities` |
| 不给模型挂状态标签 | 这个模块只答「对外有哪些模型、装得下多少」；可用性由网关按账号池现况决定，近 7 天的 `ok` / `fail` / `queued` 是历史计数而不是此刻状态（一条失败请求就把模型标成「异常」会误导），故一行里**没有任何状态标签** |
| 数据来源 | 模型名与元数据来自 `GET /web/api/state` 的 `models`（`{model, cid, meta}`，按模型去重）；平均 TPS 来自 `GET /web/api/usage?range=7d` 的 `models[]`，**按模型合并各渠道**（`avgTps` 取均值）—— 仪表盘不显示渠道，落点由网关按额度自动挑 |

- **不显示渠道**：仪表盘回答的是「这个模型能不能用、快不快」；「是哪家渠道在出」属于网关的调度细节，
  要看去请求日志（`GET /web/api/logs` 的 `cid` 列）。
- 内联后不再有搜索 / 筛选 / ping / 复制等工具条 —— 模型数只有个位数，这些控件是给几十上百个模型准备的。

### 一键接入（仪表盘内联）

把本机 harness 的模型配置改成网关的对外模型名（deepseek 裸名），省掉手工翻配置文件。

| 目标 | 写入点 | 改写内容 |
| --- | --- | --- |
| zcode | `~/.zcode/v2/provider_config.json`（JSON） | modelmux 供应商规则的 `api.baseUrl` 与 `personalModelIds` / `modelOrder`，并补齐 `group` / `access`；`modelConfigRules.providerModelRules` 给这几个模型补 `enabled: true`，并清掉该供应商下已下线的旧模型规则 |
| dsh | `~/.dsh/profiles/{acp,desktop,headless,web}/cordis.patch.yml`（YAML）+ `~/.dsh/.credentials.yaml` | patch 里 `providers.modelmux.models` 列表整段替换；`acp` profile 再补 `acp` 路由条目（`provider` / `model`）；凭据文件的 `refs` 补 `MODELMUX_API_KEY`（`apiKeyEnv` 指向的名字） |

- **只改模型清单**，不动 baseURL / apiKeyEnv / retryPolicy —— 现有接线通常已正确，越少改动越安全。
- **两处「不改不行」的例外**：zcode 的个人供应商规则必须带齐 `group` / `access` / `api`，
  缺任一项就整个供应商不进注册表（`setModel` 报「Provider Registry 中不存在 Model」）；
  dsh 的 `apiKeyEnv` 只是引用名，必须在 `~/.dsh/.credentials.yaml` 的 `refs` 里有对应条目，
  否则 Models 页判定该 provider 不可用。两处都只补缺失项，用户已配的密钥原样保留。
- **写前备份**到 `~/.modelmux/backups/integrate/<target>-<时间戳>/`，同目录一份 `manifest.json`
  记下每个被改文件的**原路径**与「接入前是否存在」—— 这是「一键还原」的依据（只存文件名
  无法还原：dsh 各 profile 的补丁同名、且接入新建的文件还原时要删掉）。
- **一键还原**（与接入并列的按钮）：取该目标**最新一次**备份写回；`existed:false`
  的文件删除；还原前先把**当前状态**再备份到 `safety-<target>-<时间戳>/`（可反悔）；
  **不消费备份** —— 同一份「接入前」状态可反复还原，只往清单记 `restoredAt` 留痕
  （旧版本留下的 `restored-<target>-*` 目录因此仍是有效还原源）。没有备份时如实报错；
  备份文件缺失或还原失败时整体报失败，不假装成功。
  配色**必须与接入按钮可辨**：接入是 `border-line-strong` 中性主按钮，还原是 `warn` 淡黄描边 + 淡黄底
  （`border-warn/45 bg-warn/10 text-warn`，hover 提到 `/16`）——`line` 与卡片描边同色，
  静止态会被读成禁用的说明文字。
- **幂等**：内容与目标一致时不落盘（结果只经右下角 toast 提示，卡片内不重复贴一条 —— 会和 toast 撞内容，还会让区块高度跳动）。
- **模型有更新（直显按钮）**：接入成功时把**当时的对外模型清单**记进标记文件
  （`backups/integrate/<target>.state.json` 的 `models`）；快照侧与当前对外清单做集合 diff
  （`app/integrate.ts` 的 `integrationUpdates`），已接入且有差异的卡在卡头亮一枚「更新」胶囊
  （橙点 + warn 淡底，与版本胶囊同一套提示语言），点击 = 重跑同一条接入路径（含备份），
  成功后随快照消失。差异明细只进 `aria-label` 不进正文（直显按钮方案，卡面保持极简）；
  老标记没有 `models` 字段按「判不了」处理不亮，避免误报；未接入不亮。
- **警告单独弹**：接入返回的 `warnings`（备份清单读不出、备份未登记 等）与还原返回的
  `notes`（跳过条目、备份缺失）都逐条弹 info toast。接入的 `warnings` 与 `notes`
  （「做了什么」的变更说明）分开传：混在一起会被当噪音忽略，「已接入」就成了假象。
  失败时 `warnings` 拼进 `error`（命令信封的 err 分支只带 error）。
- 实现放 app 层（`app/integrate.ts`），控制台（http 层）经 `ControlBridge.integrate` / `.restore` 注入调用 ——
  写的是客户端配置（`~/.zcode` / `~/.dsh`），不是网关运行时，故不能放在 http 层（见 `scripts/verify-layering.mjs`）。
- dsh 是**文本级**改写（共享层零依赖，不能引 YAML 解析器）：只定位 `providers.modelmux` 块下的
  `models:` 列表并整段替换，其余行原样保留（`desktop` 的 patch 里还有**其它 provider**，
  整条替换会误删）。

### 响应式适配（「被挤压时做好适配」）

导航在**顶部**（`components/LayoutSingle.tsx`），不再有固定宽的侧栏：

| 断点 | 顶部导航 | 说明 |
| --- | --- | --- |
| `< md`（< 768px） | **品牌 mark + 纯图标 Tabs + 网关状态** | 四个标签 + 品牌 + 网关状态在 390px 下要 678px，横向滚动又没有任何提示：实测用户只看到被切掉半个字的「账」，还以为「请求日志」这个页面不存在。故窄屏只留图标（`aria-label` 保留可读名），**图标按钮按触控下限 36px**（`tap-square`，实测 360 视口仍无页面级横向溢出）；品牌名 `≥ 420px` 才显示 |
| `≥ md` | **品牌 + 图标 + 标签 + 网关状态** | 全部入口一屏可见 |

内容区是**单列纵向流**（`max-w-[1400px]` 居中，页面级滚动）：窄屏不再需要抽屉/遮罩，
区块自上而下堆叠、超出即自然撑开。滚动发生在 `LayoutSingle` 的 `<main>`（`overflow-auto`），
头部常驻；右下角有**「回到顶部」悬浮按钮**（`BackToTop`）：滚动超过 320px 淡入
（`bg-overlay/85 + backdrop-blur`，桌面 40px / 触屏 36px），点击平滑回顶，回顶自动隐藏；
右下角 toast（z-60）出现时会短暂盖住它（z-40），消失后自动露出。

其余适配点：

- **顶栏右侧簇梯度收敛**：窗口越窄越先丢「能从别处拿回」的信息 ——
  控制钮 > 深浅切换 > 版本号 > web 页 > 网关地址。阈值（每档只掉一个元素）：
  地址 `<1200px`、web 页 `<1100px`、版本胶囊 `<1000px`、主题 `<900px` 隐藏；
  窗口控制钮与「运行中」恒常驻（前者是窗口可用性兜底，后者是网关存活信号）。
  宽屏下 base_url 胶囊内的 URL 不换行。
- **模型表 / 日志表**：两表都保留全列、只压间隔，窄到装不下才退成少列。
  日志表阈值 **735px**：≥735 取 **684px**（9 个固定列合计 584px + 模型列保底 100px ——
  最小宽若等于固定列之和，模型列会被压成 0、模型名逐字符竖排，2026-11-05 实测行高 321px）；
  <735 只留时间 / 结果 / 模型三列（最小宽 **340px** —— 窄屏时间格式 `HH:MM:SS` 实测 57px，
  时间列 17% 在 300px 表宽下只剩 41px 必裁秒位，2026-11-14 实测 390 视口；低于 340 转内层横滚）。
  列宽按内容实测收过（单元格左右各 4px；
  时间 `MM-DD HH:MM:SS` 93、tokens 对 130、表头「缓存命中率」60，2026-11-12 量），
  735 起面板内容宽恒 ≥ 687px，故这一档**不再出现横向滚动条**。模型表仍按 `md`（768）收敛。
  非要更窄时由 `ScrollFade` 在右缘铺 32px 渐隐提示还有列。
- **栅格行内等高的留白取向**：仪表盘的双列区（模型用量 8 列 / 模型清单 4 列）行高由较高者决定，
  较矮的一张会被 `flex-1` 拉到同高。差额**不堆在内容下方**（那是纯空白带）—— 模型用量卡用
  `justify-between` 让标题吸顶、说明贴底，空白落进卡内成为合理留白（1600 宽实测：改前卡底空 54px，
  改后 17px，即只剩内边距）。
- **内容不满一屏时不留空白**：`LayoutSingle` 的内容容器是 `flex min-h-full flex-col`，
  页面根节点用 `flex-1` 才能拿到「撑满视口后的剩余高度」。请求日志页表格区据此填到视口下缘
  —— 用 `h-full` 不行：父级只声明 `min-height`，百分比高度会解析成 auto，行数少时视口下缘空一大块
  （1600×1000 实测空约 300px）。
- **最近请求行**：模型名与状态点包成一组吃满剩余宽度，数值列靠右对齐。不要用「固定宽模型列 +
  `flex-1` 空 spacer」的写法 —— 宽屏下那个 spacer 会撑成几百像素的孤立空白（1600 宽实测 700px）。
  **列的取舍必须靠「少渲染 `<td>`」，不能用 `hidden md:table-cell`** ——
  `display: none` 的 `<td>`/`<col>` 在 `table-layout: fixed` 下**仍占列槽位**：
  实测（390 视口）模型列只拿到 48px，而表头那行按自己的算法拿到 238px，**表头与表体还会错位**。
  故由 `matchMedia('(max-width: 767px)')` 与 Tailwind `md` 同口径地判窄屏，再用**同一份
  列定义**驱动 `<colgroup>` / `<th>` / `<td>`，保证三者恒等。
- **触控目标**：`.tap` / `.tap-square` 只在 `< md` 生效，把可交互元素垫到 ≥ 2.25rem（36px）。
  不取 WCAG 2.5.5 建议的 44px：手机视口本来就小，44px 的刷新按钮、下拉、分段控件在窄屏上
  是显眼的大按钮（2026-11-14 实拍裁决取紧凑档）；36px 配合行间距仍可点准。
  `min-height/min-width` 天然压过既有的 `h-*`/`w-*`，
  所以直接加在定尺寸按钮上即可。`≥ md` 不限 —— 桌面是鼠标，放大只会白白牺牲信息密度。
- **字号下限 12px**：徽标 `.pill` 与所有 10/11px 文本统一到 12px。
- **账号卡**：窄屏只保留**剩余额度数值**（标签、「今日消耗」「今日 tokens」按卡片宽度逐级恢复）——
  一行装不下「标识 + 状态 + 额度 + 两个 36px 操作键」时，先保「还剩多少」。
- **Token 活动热力图**：内层恒 **700px 最小宽**、列缝 2px，窄视口横向滚动（53 列摊缝后
  手机宽度每格不足 3px、月份标签互相叠字；600px 下每格仅 8px，无数据的 0 档格几乎隐形，
  点阵区域看起来像一片空白 —— 2026-11-14 实拍裁决）；面板内容宽 ≥700 的桌面形态基本不变。
- **模型偏好**：窄屏（`< md`）切**两列网格**一行放完，下拉 `fill` 模式填满列宽（360 视口
  两列各 ~144px）—— 桌面 176px 定列在手机上折成竖排居中的大块；桌面 ≥ md 不变。
- **未知路径兜底**：路由表外的路径（历史书签、旧链接如 `/web/models`）重定向回仪表盘 ——
  无兜底时没有任何路由命中，连布局壳都不渲染，整页只剩底色。
- **接入开关的触控垫**：`.tap-square` 放在开关**按钮**上、22px 视觉轨道缩进其内 ——
  `.tap` 若直接加在轨道按钮上，min-height 会把轨道撑成 44px 圆饼、滑块贴在顶端错位。
- **登录弹窗**：左栏（渠道 + 步骤概览）窄屏**堆叠**到顶部并改成横排 ——
  固定 224px 在 480px 下会把右侧流程挤到 ~200px。
- **统计条 / 总览条 / 工具条**：一律 `flex-wrap`；账号池总览条按 **chip** 分组
  （中性底 + 圆角 + `whitespace-nowrap`），折行后逐行对齐，标签与数字同处一个视觉单元。

**量化判据**（`.tmp/probe-web-verify.sh`：三页 × 360/390/768/1024/1280/1440/1920，改 UI 后必跑）：
360 与 390 下三页**触控 < 36px = 0、字号 < 12px = 0、`title` 属性 = 0、页面级横向溢出 = false**，
且模型表**表头与表体的列宽数组逐列相同**；1280 与改动前一致（模型列 488px）。
图表内的密集数据目标（热力图格子、折线数据带，标了 `data-viz-target`）豁免 36px 判据 ——
理由见 [USAGE-STATS.md](./USAGE-STATS.md) §4.2。

### 账号池页的排布

渠道卡用 **按列分发的瀑布流**（`lib/card-columns.ts`）：列数由容器实测宽算出（单卡最小 340px，
1400px 容器下 3 列），列内自上而下紧挨着排，列间从左到右；没有任何跨卡的横向对齐约束。
单卡窄于约 340px 时中文账号名与额度条会互相挤压（实测「塞西莉亚4412」被截断），
340px 是下限，`min(340px, 100%)` 是窄屏收口（不然 360 视口会被顶出横向滚动）。

- 深色是**唯一主题**，不留浅色分支与切换入口。
- 授权链接 / 登录进度只在**登录弹窗**内渲染（遮罩与 ESC 不关），不出现在其他页面。
- 登录弹窗三种形态，由 `state` 决定：
  - **两步登录**（`login_input` 非空，如 loomy 短信验证码）→ **只渲染一个三行表单**，
    不摆授权步骤时间线：
    `手机号（+86）` 输入框 / `验证码` 输入框（左）+ `获取验证码`（右）/ `登录`（左）+ `取消`（右）。
    后端仍是两次顺序的 `requestInput`（先要手机号 → 发码 → 再要验证码），表单把它映射成三行：
    手机号那一步「获取验证码」可点、验证码框与「登录」禁用；码发下来后二者解禁、
    按钮转「已发送」。两个输入的值挂在**弹窗**上（后端换一次输入请求就重渲染，
    挂在子组件上会被清掉）；
  - **扫码**（`qr_url`）→ 二维码 + 确认步骤；
  - **授权链接**（`auth_url`）→ 复制链接 + 官方页完成 + 自动回调，**三步**。
    第四步「手动粘贴回调链接」已删：控制台与网关同机，回调必然到得了本机端口，
    粘贴框对 Web 端是纯冗余（CLI 仍保留 `pasteCallback` 兜底）。
- **准备期画骨架**：弹窗挂载到「本轮第一个状态更新到达」之间只显示骨架，
  绝不渲染上一轮残留的 `done` / `error` / 旧授权链接。
  后端 `triggerLogin` 也会**同步**清空旧状态（`beginLogin()`），
  两边一起才封得住那个最长 3 秒的窗口（2026-10-26 主人反馈「一开始就显示登录成功」）。
- **登录成功后弹窗自动关闭**：页面轮询 `/web/api/state`，一旦 `login_result` 变成 `done`，
  立刻关闭弹窗、刷新账号池 / 登录态 / 账本，并主动重查该渠道额度（新账号额度与旧账号不同）。
  判据要求先观察到别的结果（`idle`），避免上一次登录残留的 `done` 误关新弹窗。
  **登录结果不在 `ui_state` 里**：那个字段只表示网关状态（probing / login / running），
  一次登录失败不该让右上角永久显示「登录失败」（详见下方「状态快照」）。

## 账号展示与额度

- 渠道头**只显示小写 cid**（如 `catpaw`），不显示展示名与 `ok` 文字；状态只用小圆点。
- 账号主标识**渠道给什么就显示什么**，前端不做脱敏：取用顺序
  `name`（渠道给的可读标识：nickname / 用户名 / 邮箱 / 手机号）→ `label` → `uid` → `key`，
  取到即原样渲染。
  **要不要脱敏由渠道/上游决定**（拿不到明文就别存），前端不再统一加工 ——
  前端统一打码会让同一页面出现两套口径：astudio 给的是明文手机号、lobsterai 上游只给打码手机号，
  看起来自相矛盾。实测同一页：astudio `13800138000`（明文）、lobsterai `138******00`（上游只给密文）。
- 额度**按账号**查询：后端用每个账号自己的凭证调用
  `billing.fetchCredits({ credential, refreshOn401: false })`，结果写进账本
  `accounts[key].credits`；账号行右侧显示**剩余额度数值**（带千分位、最多 2 位小数，
  **不显示「积分」「credits」这类单位**），卡片够宽时再恢复「剩余额度」标签与「今日消耗」。
- 百分比以**当前额度窗口内第一次账单**为 100% 基线（实现见 `pool-usage.ts` 的 `pickBaseline`）：
  窗口键取渠道声明的 `quotaPeriod().resets_at`，没声明才回落本地日期；窗口滚动或同一窗口内
  `remain` 回升（奖励到账）时重设基线。**没有基线或 `remain` 不可用时不显示百分比** ——
  不回退上游 `remain_percent`（它是窗口占比，常年 100，会给出误导性的满格）。
  也不用上游 `size` 当分母（各渠道口径不一）。
- 查询失败显示「额度查询失败」，不把未知显示成 0。
- **今日签到**（额度详情面板的最后一行）：读本地台账，不查上游。渠道 `capabilities.signin = false`
  时整行不渲染；按账号签到的渠道（`signin.perAccount`）用该账号的记录，其余渠道用渠道级记录。
  **三种情况分开说**：领到了 → `已签到 09:12 +1,200 积分`（额度按**四口径阶梯**：
  渠道自报的 `reward` → 渠道公布的每日发放额 `dailyReward` → 领取前后实测差值 `delta` →
  跨额度窗口对比 `carry`；前三者都拿不到才用 `carry`，此时追加「（估算）」标注，
  不把弱口径伪装成准确数字。没涨 / 查不到就不显示，不编 0）；
  有当天探测结论且上游明确没有可领活动 → `今日无可领`（不附上游原话 —— 面板只回答「签没签 / 领了多少」）；
  其余 → `未签到`。`supported` / `per_account` / `claimed_today` / `at` / `reward` /
  `reward_source` / `probe` 由 `accounts` 命令透出，探测结论由自动签到调度器落盘
  （`signin-ledger.recordProbe`，当天有效）。
  额度对**旧版本写的记录**（没有 `reward` 字段）与**异步入账**由调度器**有界重试**补回
  （只对当天的记录，最多 `REWARD_MAX_TRIES = 4` 次；每次重试累加 `rewardTries`，
  补完写 `null` 表示「问过但报不出」，不会每轮都打扰上游）。
  口径与实现见 [POOL-ARCHITECTURE.md](./POOL-ARCHITECTURE.md) §3.6。
- **冷却 / 熔断到点时刻**：只给**具体恢复时刻**（`冷却中 · 今天 20:46 恢复`，跨天自动补日期
  `11-07 10:10`）—— 用户要的是「什么时候能用」，相对时长与上游错误原文属多余信息，不再展示
  （错误原文仍留在 `cooldown_reason` 里供排障）。
- 账号池页与请求日志页的**刷新按钮**共用 `components/RefreshButton.tsx`：忙态下图标旋转
  （`motion-reduce:animate-none` 时只保留禁用态）、按钮禁用、`aria-busy`，并保底
  `MIN_SPIN_MS = 420ms` 的可见时长。本机网关几十毫秒就返回，没有这层保底用户「看着」像没刷新。

### 交互铁律：**正文信息不得只靠 hover 才能看到**

- **正文信息**（卡片 / 列表里的数据与说明）必须**直接可见**（写进正文，允许换行、不裁切），
  或放进**点击后**才出现的详情区（弹窗 / 抽屉 / 展开行）—— 截图、投屏、触屏与键盘操作都
  拿不到 hover 内容，关键信息不能依赖悬停。
- **原生 `title=` 属性仍然禁用**（浏览器原生 tooltip 样式不可控、无障碍差）；
  按钮的无障碍名称用 `aria-label`（不产生可见气泡）。
- **例外：图表数据详情用自绘 hover 浮层**（2026-10-30 放宽）—— 数据点密度高、
  点击不合适，用 `components/usage/ChartTooltip.tsx`（portal 到 body、`pointer-events-none`
  不挡鼠标），形态对齐 ZCode 的「使用统计」；热力图 / 环形 / 趋势图三块的浮层即此实现。
  趋势图的浮层**横向跟随数据点**（不是鼠标）：图形按容器宽度 1:1 渲染后，鼠标 X 只用来
  选「最近的一天」，浮层位置由该数据点的屏幕坐标决定 —— 否则分辨率变化时浮层与所指日期错位。
  新增悬停交互先确认属于「图表数据详情」这一类。
- 图表的 hover 浮层里**不承载独占信息**：同样的数值必须在浮层之外也有出处（图例、
  KPI、详情区），浮层只是「指着看」的快捷方式。

这条只管**信息**，不管**低频动作按钮**：账号行上的切换 / 删除默认 `opacity-0`、
`group-hover` 才出现（`group-focus-within` 保键盘可达，`pointer-coarse` 触屏常显）。
信息一个都不能藏，动作可以 —— 动作藏了只是少一条捷径，信息藏了等于没有。

### 登录链接：**复制，不弹新窗口**

「添加账号」弹窗里的授权链接，点击只做**复制到剪贴板**（剪贴板不可用时静默失败，
用户仍可手动复制下方那一行），**不调 `window.open`、不用 `target="_blank"`** ——
由用户自己决定在哪个浏览器 / 窗口打开。页面里不应出现「点授权链接 → 自动开新标签页」。

「添加账号」是**强制重新授权**（后端 `force`），但**不会先删掉现有凭据**：
授权要等人操作，期间旧凭据继续可用；只有新凭据落盘（原子覆盖）才替换它。
（旧实现先删凭据，授权没走完渠道就掉线，界面出现「未登录 + 账号生效中」的矛盾状态。）

### 不可逆操作：**二次确认**

删除账号（`onRemove`）不可逆（**生效账号会同时登出**），必须先确认：点垃圾桶弹出
`ConfirmDialog`（标题「删除账号」+ 渠道 / 账号名 + 「取消 / 删除账号」），只有点
「删除账号」才真调 `onRemove`。规则：

- 弹窗**挂到 `document.body`**（`createPortal`）：账号卡带 `@container`，它隐含
  `contain: layout`，会成为 `fixed` 后代的包含块，不 portal 就会被卡片裁切；
- 同一时刻只允许一个账号处于待确认态；
- 切换账号、开始删除（`busyKey !== null`）时清空确认态；
- 点遮罩 / 按 ESC / 点「取消」都是取消，不产生任何副作用；默认焦点在「取消」上。

### 账号状态恢复：全靠自动路径，不设手动解除入口

异常（`error`，连败熔断）与冷却（`cooldown`，额度耗尽）都能**自愈**：熔断到期自动半开试探、
冷却到期惰性恢复、请求成功清零连败，三条路径都在请求路径上自动完成，不需要用户干预
（语义见 [POOL-ARCHITECTURE.md](./POOL-ARCHITECTURE.md) §2.4「额度耗尽 → 账号冷却」与「熔断自动恢复」）。因此账号行上
**不提供手动「解除」按钮**。

- 后端 `resetAccount` 命令仍在（`/web/api/commands` 仍接受，等价 `clearAccountState`），
  但控制台**不设入口**：自动恢复已覆盖全部可恢复情形，多一个按钮只会多一处可误解的操作。
- 唯一不可自动恢复的是 `unauthorized`（凭据本身失效）—— 它本来就不许解除，只能重新登录；
  界面如实显示状态并引导走「重新授权」。

## 技术栈与构建

- React 19 + TypeScript + Vite 8（`base=/web/`）+ Tailwind CSS v4 + TanStack Query v5 +
  react-router v8 + lucide-react 图标 + **Radix UI（headless 原语）**。
- **Radix 用在哪**（2026-10-26 引入）：`@radix-ui/react-toast`（轻提示）、
  `@radix-ui/react-dialog`（登录弹窗）、`@radix-ui/react-alert-dialog`（删除确认）。
  选它的理由是 **headless** —— 只给行为（焦点陷阱、焦点归还、滚动锁、aria 接线），
  不给视觉，所以控制台的 Codex 近黑单色风格完全由 Tailwind 令牌决定，没被组件库带跑。
  （antd / MUI 自带一整套设计系统，引进来要么覆盖它、要么推翻现有设计。）
- **`packages/ui` 不受依赖白名单约束**：`scripts/verify-contract.mjs` 的 `DEP_ALLOW`
  只管渠道包与 `packages/cli`；UI 包本来就有 15 个第三方包（含 devDependencies：React / Tailwind /
  Vite / TanStack Query / react-router / Radix UI / lucide / react-markdown 等）。
- `npm run build` 顺序：`tsc -b` → `vite build packages/ui` → cli bundle →
  `scripts/copy-ui.mjs` 把产物拷到 `packages/core/gateway/dist/ui` 与 `packages/cli/dist/ui`
  （**少拷一份，全局 `mx web` 就报「UI 未构建」**）。

### 静态资源落点：必须走 `src/assets/`，不要放 `public/`

页面图标在 `packages/ui/src/assets/favicon.svg`，由 `index.html` 以 `/src/assets/favicon.svg`
引用。Vite 会把它打进 `assets/` 并加内容哈希（产物形如 `/web/assets/favicon-<hash>.svg`）。

**为什么不能放 `public/`**：console handler 只托管两个静态位置 —— 前缀根 `/web/`（返回
`index.html`）与 `/web/assets/*`；其余 GET 一律走 SPA 回退（`console.ts` 的
`serveStatic(res, WEB_UI_INDEX)`）。放 `public/` 的 `/web/favicon.svg` 会被回退成 HTML
而拿不到 SVG。同理，图标不要声明成 `/web/favicon.svg` 这类前缀根路径。

在 `index.html` 里显式声明 `<link rel="icon" type="image/svg+xml" href="/src/assets/favicon.svg">`
还有第二个作用：浏览器不再去要默认的 `/favicon.ico` —— 那个路径在网关根下不存在，
会以 `not_found` 写进 `access/<date>/failure.log`，属纯噪音。

## 数据通道

- `GET /web/api/state`：登录快照（ui_state / **login_result** / message / auth_url / qr_url / **login_input** / 端点 / **version** / **update**），
  外加模型池视图所需的 `models`（`{model, cid, meta}` 矩阵）/ `channel_caps`（各渠道能力位）。
  - `version` 是仓库 `VERSION` 常量（唯一真相是根 `package.json` 的 `version`，见
    [CONTRACT-TS.md](./CONTRACT-TS.md) 的发布约定），顶栏版本胶囊的数据源；旧网关缺失该字段时
    胶囊不渲染（不留空壳）。
  - `update` 是版本更新提示（`{available, version, notes, url, checkedAt}` 或 `null`），
    由网关后台**每天检测一次**填充（见 runtime/update-check.ts）；无提示时胶囊不出现橙点。
  - `login_input` 非空 = 渠道在等用户输入（两步登录，如 loomy 的短信验证码）。
    界面据此把登录弹窗切成**输入卡**；`null` = 没有待回答的输入。
  - **模型元数据走进程内缓存**（跨渠道索引 `buildCrossModelIndex`，30 秒 TTL +
    目录变化/池集合变化时显式失效）：建一次要枚举全部渠道目录 × 每模型查规格，实测约 400ms
    且**同步阻塞** —— 控制台 3 秒轮一次，不缓存就会把事件循环占住约 15%，同页面的
    accounts / logs 请求全在排队（症状：进入账号池要等很久）。缓存命中后 `/api/state`
    稳定在几十毫秒。
- 前端对所有轮询查询用 **`staleTime` = 轮询间隔** + `placeholderData: (prev) => prev`：
  间隔内再进页面**直接用缓存**（不发网络请求，也不清空成骨架）；首访没有旧数据时仍走骨架。
  轮询间隔见各页：state 3s、overview 5s、logs 5s、accounts 15s / logins 10s / billing 60s、
  `usage?range=7d`（账号池的今日 tokens）60s。
- `POST /web/api/commands`：动作分发（login / status / **models** / billing / accounts /
  activateAccount / **resetAccount** / removeAccount / syncPool / pasteCallback /
  **submitInput** / **cancelInput**）。
  - `billing` 支持 `args.refresh: true`（真实重查各渠道账单）与 `cid` 过滤（单渠道刷新）。
    账单行以**渠道**为主维度：上游目录里没有对外家族模型的渠道（只有家族外型号的渠道）
    进不了统一模型池，但只要 `capabilities.billing` 且账本有它的条目，就会补一行
    （否则这类渠道在账号池页的额度恒为 0 —— 2026-11-06 实测修复）。
  - `resetAccount`：解除 `error` / `cooldown` 标记（不动凭证）；`unauthorized` 会被拒绝并给出原因。
    后端保留的命令调用面，UI 已无入口（账号状态靠自动恢复，见上文「账号状态恢复」）。
  - `pasteCallback`：手工兜底通道，把用户粘回的回调链接喂给等待中的登录流程。
    raccoon 等授权码渠道现在优先走**本地 HTTP 回调自动完成**，Web UI 已不提供粘贴入口
    （控制台与网关同机，回调必然到得了本机端口）；该动作保留给 CLI 与非本机场景。
  - `submitInput`：把两步登录的输入交回给等待中的渠道；`cancelInput`：弹窗关闭时调用，
    让等待输入的渠道立刻收尾（不调用会挂到 10 分钟超时）。
- `GET /web/api/logs`：访问日志查询（只读）。参数 `date` / `outcome` / `cid` / `model` /
  `stream` / `slow` / `q` / `limit`（上限 500，默认 100）/ `offset`。
  返回实际日期（当天无日志时后端回落到最新日期）、可选日期与渠道、`stats`（基于**未过滤**读窗口的
  当天概览）、`total`（命中筛选数）、`entries`。
  - 读窗口有界：每个 outcome 文件只读尾部 1MB、总扫描 2 万行；超出时 `truncated=true`，
    界面据此把统计标注成「只覆盖最近 N 条」，而不是假装是全量。
  - 只读 `success` / `failure` / `other` 三个分桶 —— `slow.log` 是它们的并行副本，
    一起读会让慢请求在列表里出现两遍。
  - **固定只看模型请求**（`paths === MODEL_REQUEST_PATHS`，三协议 `/v1/chat/completions` / `/v1/messages` / `/v1/responses`）：`/health` 等非模型请求同样落盘，
    但不进这个列表（路径常量在 `runtime/log-store.ts`）。
- `GET /web/api/usage`：用量统计聚合（只读）。参数 `range`（`today` / `7d` / `30d` / `90d` / `365d` / `all`，默认 30d；`365d` 只供热力图，`all` = 累计）。
  服务端逐日全量扫描 access 日志（不走日志页的读窗口上限），已过去的日期带进程内缓存；
  口径与指标公式见 [USAGE-STATS.md](./USAGE-STATS.md)。
- `GET /web/api/logs/payload`：按 `id`（+ 可选 `date`）读回请求正文抓取记录，
  返回 `records`（`phase=client` 的客户端原样体 + `phase=upstream` 的各次上行体）。
  恒开启：正文抓取不可关闭（见 [LOGGING.md](./LOGGING.md) §9）。
- 这几个只读端点**带同源校验**（与 `POST /api/commands` 同款）：日志与用量含模型名与渠道，
  比 `/api/state` 更不该被跨源页面读到；无 `Origin` 头时放行，curl / 脚本不受影响。
- `POST /web/api/theme`：切主题；`POST /web/api/retry-login`：重试登录。
  两者在 `console.ts` 里已实现，但当前 UI **没有入口**（深色是唯一主题，也没有重试登录按钮）——
  前端 `lib/api.ts` 里的 `setTheme` / `retryLogin` 只是保留的调用面。
- `GET /web/api/overview`：仪表盘聚合视图（一次拉全）。返回当日 KPI
  （`usage`：请求/成功/失败/慢/平均耗时/tokens）、每渠道状态（`channels`：模型数 +
  账号健康分布 + 今日成败）、模型池概览（`model_pool`：总数/免费/多模态/思考）、
  最近 5 条请求（`recent`：时间 / **渠道** / 模型 / 结果 / 耗时 / tokens / TPS；渠道列窄屏（< 768px）让位
  —— 390px 下 tokens 与 TPS 是主信息；失败与中断额外带
  `error` + `message`，界面把状态码与原因直接摊在同一行、超长截断）。带同源校验，5 秒轮询。
- `/api/commands` 返回值由前端 `lib/api.ts` 统一**解包 `data`** —— 页面不要再取一层
  `.data`（双重解包会导致 tab 崩溃）。

## 账本维度

账本主维度是**渠道**（used / 冷却 / billing_at），另按**生效账号**拆分 ok / fail 计数
（`ChannelLedger.accounts[key]`），控制台账号池卡片按「渠道 × 账号」展示；
账本数字记在请求发生时的当前生效账号头上。
