# Web 控制台（mx web）

`mx web` 把 React 管理看板挂在网关的**唯一端口**上（`http://127.0.0.1:4412/web/`，
控制台 API 在 `/web/api/*`），没有独立进程与独立端口。

## 设计系统（`packages/ui/src/index.css`）

视觉语言参照 **Codex / ChatGPT**：**纯近黑单色系**。侧栏比主区更深、浮层比主区更浅，
层级只靠底色差与留白表达；**accent 就是白**（主按钮白底黑字、选中态白色高亮），
不用任何彩色品牌色；状态语义色保留但饱和度压低，只出现在「需要人看」的地方。

UI 的配色、层级与圆角**只在 `index.css` 的 `@theme` 里定义一次**，组件一律用令牌类，
不直接写 `gray-900` / `sky-500` 这类原始色 —— 换主题只改这一处。

| 组 | 令牌类 | 用途 |
| --- | --- | --- |
| 表面（四个深度层） | `bg-surface` `#171717` / `bg-canvas` `#212121` / `bg-raised` `#2f2f2f` / `bg-overlay` `#3a3a3a` | 侧栏（最深）→ 主区 → 卡片与输入盒 → 悬浮层与选中底 |
| 描边 | `border-line` `#383838` / `border-line-strong` `#4d4d4d` | 几乎不用；需要分块时才出现，且刻意看不清 |
| 文字 | `text-ink` `#ececec` / `text-ink-soft` `#b4b4b4` / `text-ink-faint` `#8e8e8e` | 主 / 次 / 弱 |
| 语义 | `brand` **`#ffffff`** / `free` / `warn` / `danger` | **accent = 白**：主按钮是白底黑字（`text-[#171717]`），不是彩色底 |

三个组件类与一处动效：

| 类 | 用途 |
| --- | --- |
| `.panel` | 唯一的容器形态（`rounded-2xl border border-line bg-raised`），端点盒、渠道卡共用 |
| `.panel-title` | 面板标题（图标 + 文字，14px 常规字重 —— 不靠加粗靠留白） |
| `.pill` | 徽标（状态 / 计数）；中性底，不铺彩色底 |
| `.nav-item` | 侧栏导航项（纯文本 + 圆角 hover 底；选中态 `bg-raised`，不用彩色底） |
| `.live-dot` | 网关状态灯的呼吸动效（`prefers-reduced-motion` 下自动关闭） |

约定：

- 圆角只有两档：容器 `rounded-2xl`、行内元素 `rounded-lg`；主按钮 `rounded-full`。
- **单色系**：除状态语义色（免费/冷却/错误）外不出现任何彩色；
  主操作按钮一律 `bg-brand text-[#171717]`（白底黑字）。
- 标题是**无衬线常规字重**（ChatGPT 的标题不靠加粗靠留白），不用衬线字体。
- 数字用等宽数位（`.tabular`），统计值变化时不抖动。
- 键盘可达：`:focus-visible` 有统一聚焦环（鼠标点击不显示）。
- 图标统一用 `lucide-react`，尺寸三档：12（小徽标）/ 14（行内）/ 16（面板标题）。
- **品牌 mark 是内联组件**（`components/BrandMark.tsx`，极简鲸鱼剪影 +
  分叉尾鳍 = 多条渠道，单色、16px 清晰），与 `assets/favicon.svg` 同形（白色）；
  颜色跟随 `className` 的 `text-*` 令牌（侧栏用 `text-ink`）。

## 页面结构

| 页面 | 内容 |
| --- | --- |
| 仪表盘 `/web/` | 接入盒（base_url / chat_url / endpoints）+ KPI 四格（今日请求成功率 / 失败慢请求 / 平均耗时 / tokens）+ 双列四卡（左：渠道状态 + 最近 5 条；右：模型池概览）。**网关控制（状态 + 暂停/重启）常驻侧栏左下角**，不随页面内容变化（网关异常时 main 是骨架，这里仍可操作）。数据来自 `GET /web/api/overview`（KPI+渠道+模型池+最近请求）+ `GET /web/api/state`（接入盒）。每 3-5 秒自动轮询。设计见 [DASHBOARD-DESIGN.md](./DASHBOARD-DESIGN.md) |
| 模型列表 `/web/models` | 可用模型表（模型名 / 倍率 / 最大上下文 / 输出上限 / 思考模式 / 输入模态 / 复制），数据与仪表盘同源（每 3 秒轮询），不设分页 |
| 账号池 `/web/accounts` | **右上角「刷新」**（一次性失效账号 / 登录态 / 额度 / 快照四路查询）、添加账号（**登录引导弹窗**）、总览条（正常/冷却/异常/未登录计数）、渠道卡片**两列网格**（小写 cid + 账号列表：单行 = 状态点 + 可读昵称/用户名 + 状态 pill + 剩余额度 + 切换/**解除**/删除；**每卡固定 2 个账号位，超过 2 个折叠为「展开剩余 N 个」**） |
| 日志 `/web/logs` | 请求级访问日志（数据源 `~/.modelmux/logs/access/<日期>/*.log`，字段见 [LOGGING.md](./LOGGING.md) §3）。请求正文抓取**恒开启**（留底，无开关，见 [LOGGING.md](./LOGGING.md) §9）。三段：**统计条**（请求 / 成功率 / 成功·失败·中断 / 慢 / 平均耗时 / tokens，大数带「百万 / 亿」单位）、**筛选栏**（结果分段 + 渠道 + 日期 + 关键词（模型名、request id、错误）+ 只看慢 / 只看流式；筛选变化自动回第 1 页）、**表格 + 吸底分页条**（时间含年月日 / 结果 / 模型 / 流 / 耗时 / tokens 入·出，数值列右对齐；分页条 sticky 跟随视口底部，随时可翻页：左「共 N 条 · 每页 10/20/50（默认 20）」，右上一页/下一页）。点行**展开**元数据详情（request id 可复制、method+path、三段耗时、请求规模、错误码与说明、usage）；**最右侧「上下文」按钮**弹窗展示整段 message 对话（系统提示词 / 用户 / 工具调用与命令 / 工具定义逐条渲染，**AI 回复按 Markdown 渲染**，GFM 表格与代码块可用且 HTML 一律转义；超 1600 字符折叠为「展开全部」；每条消息右上角可**复制本条消息**，顶部**复制全部内容**）。5 秒轮询，展开、翻页或弹窗打开时暂停 |

> 日志页对网关 `error` 状态**豁免骨架**：控制台与网关同进程，能读到 `ui_state` 就说明进程还活着、
> `/api/logs` 也就能用 —— 而排查异常恰恰最需要看日志。`down`（网关真不在）与状态查询失败时
> 日志同样拿不到，仍走骨架（见 `components/Layout.tsx`）。

### 为什么仪表盘首屏是「接入盒」

参照 ChatGPT 的首屏：一块大的圆角输入盒占据视觉中心，周围留白。
这里最高频的动作是**把 base_url 抄走**，所以端点做成首屏主体、统计压成一行内联数据。

### 为什么账号卡最多两列

三列时单卡仅约 380px，中文账号名与额度条会互相挤压（实测「塞西莉亚4412」被截断）。

### 账号卡的布局统一（固定 2 账号位 + 单行扁平 + 折叠）

多账号、多状态曾把页面撑得参差（2026-10-25 主人反馈）。2026-10-26 主人定稿的布局规则：

1. **每张卡固定 2 个账号位**（无论是否登录、有无账号）：
   - 未登录 / 0 账号 → 2 个空位占位
   - 1 个账号       → 1 个真实账号 + 1 个空位
   - 2 个账号       → 2 个真实账号（刚好填满，不折叠）
   - > 2 个账号     → 2 个真实账号 + 折叠条（展开剩余 N 个）

   每张卡的高度因此**完全可预期**（卡头 + 2 个 44px 账号行 + 固定高度的卡底条），
   账号多的渠道不再把页面撑参差，空卡也不再矮一截。
2. **账号行恒定单行、44px**（`h-11`）：状态点 / 名称 / 状态 pill（生效中、冷却中、不可用…）
   / 额度（条 + 数字 + 百分比）/ 操作，全部横向排开。
   **不设第二行状态说明** —— 早期那条 16px 的说明行即使没内容也占位，既撑高卡片
   又让信息显得零碎（2026-10-26 主人要求「内容保持尽量扁平」）。
3. **额度区按卡片宽度逐级露出**：容器查询（卡片根节点 `@container`）而不是视口断点 ——
   同一视口下卡片可能整行、也可能只是两列里的半行。
   窄 → 只留数字；`@min-[380px]` → + 进度条；`@min-[460px]` → + 百分比。
   百分比是冗余表达（数字与条已经说明一切），压缩时最先砍掉。
   空位占位行必须镜像同一套断点，否则两行对不齐。
4. **切换 / 删除默认隐藏**，鼠标移到该账号行才出现（`group-hover`）；
   `group-focus-within` 保证键盘可达，`pointer-coarse`（触屏）常显。
   删除走**确认弹窗**（见下文「不可逆操作」）。
5. **折叠起点 2**：每卡默认露 2 个账号，超过 2 个才折叠为卡底「展开剩余 N 个账号 / 收起」
   （复用模型分组表的折叠模式，`aria-expanded`）；生效账号恒排首位，不会被折掉。
6. **卡底条恒渲染**：不需要折叠时用同高同底色的静态说明（`已全部显示` / `暂无账号`）占位 ——
   只在 > 2 个账号时才出折叠条的话，多账号的卡会比 1-2 个账号的高一整条，两列并排卡底参差。

### 模型区（`components/ModelExplorer.tsx`）

**为什么不是「双列渠道卡」**：渠道卡按内容高度排进两列网格，网格行高取最高那张卡 ——
模型数差距大时，模型少的一侧被拉出**等高的空盒子**（实测 30 个 vs 9 个并排，页面直接失衡）。
现在改成**纵向的渠道区块**：每个渠道一个全宽表块，高度 ∝ 它的模型数，
**结构上不可能出现空洞**。

| 元素 | 形态 |
| --- | --- |
| 工具条 | 搜索（模型名或渠道名）/ 渠道筛选下拉 / 「只看免费」开关 / **视图切换**（分组 \| 扁平）/ 命中计数 |
| **分组表**（默认） | 每渠道一个**独立表块**：band 行（`● cid` + 模型数 + 免费数 + 可吃图数 + 倍率区间 + 折叠）+ 该渠道自己的 `<table>`（紧凑表头 + 模型行）；**默认每组只显示前 3 个**，其余折叠可展开 |
| **扁平表** | 全部模型按倍率升序排成一张表，渠道作为一列 —— 回答「最便宜的模型在哪」 |
| 模型行 | 模型名（等宽）\| 倍率（0 → 绿色「免费」徽标）\| **最大上下文** \| 输出上限 \| **思考模式**（档位列档位，无声明 → 「不支持」）\| 输入模态（可吃图 → 「文本+图」徽标）\| 复制按钮 |

- 表格是**真 `<table>`**：分组视图里**每个渠道一张表**（各带 `<thead>`），
  列天然对齐、屏幕阅读器可读。
- **每个渠道自带横向滚动容器**（`overflow-x-auto`）：整张表只有一个底部滑块时，
  得滚到页面最下方才够得着，而且一动就带着所有渠道一起滚（2026-10-26 主人反馈）。
  现在每组独立滚动、独立列宽；band 行留在滚动容器外，横向滚动时渠道名不会跑掉。
  表头因此每组一份（共用一份会让滚过的那组列名与内容错位），做得紧凑（`py-1.5` + 10px 字）。
- 排序口径与徽标口径**必须一致**：倍率 0 与「订阅制无倍率概念」算免费；倍率**未知**排最后，
  不冒充免费。
- 「订阅制」由服务端的**能力位**判定：`/web/api/state` 的 `channel_caps[cid].billing` 为 `false`
  即没有额度/倍率概念（渠道在 `ChannelConfig.capabilities` 里声明）。
  ⚠ 前端**不得硬编码渠道名** —— 必须读服务端能力位，否则新增渠道会漏标；
  账号池页走的是同一个能力位（`unsupported`），两处口径一致。
- 数据来自 `/web/api/state` 的 `model_info`（共享层 `PoolModelMeta`）——
  上下文窗口、输出上限、输入模态、**思考档位**本来就有。
- **「最大上下文」不是「上下文」**：上下文档位表（qoder 的 `context_config`）取**最大档**，
  客户端永远走最大上下文，所以列名与取值口径一致（见 POOL-ARCHITECTURE §2.6）。
- **思考模式按渠道声明如实显示**：`effort` 为 `null`（渠道没声明）就写「不支持」，
  **不编档位** —— 旧版给所有模型都填了 `low/high`，把「不知道」显示成「支持」。
  档位名英文 → 中文映射（`low`→低、`medium`→中、`high`→高、`xhigh`→超高、`max`→最大、
  `minimal`→最小、`none`/`off`→关闭），未知档名原样显示。
  档位按**强度重排**后展示（上游下发顺序是随机的，实测 qoder 给的是
  `xhigh/high/low/max/medium`），顺序表见 `THINKING_LEVEL_ORDER`。
  档位来源分三种（`sources.effort`）：上游目录声明、渠道官方规格（`spec`，渠道把官方
  文档的档位抄进自己的规格表）（窗口 / 输出 / 档位排序见 `THINKING_LEVEL_ORDER`）。
- 窄屏（< 768px）隐藏「最大上下文 / 输出上限 / 思考模式」三列，避免挤压换行；
  表格本身是 `overflow-x-auto` 的滚动容器，列放不下时**横向滚动**而不是挤成一团。

### 响应式适配（主人 2026-10-24 要求「被挤压时做好适配」）

侧栏是唯一「固定宽」的部件，也是窄屏下最先崩坏的地方：

| 断点 | 侧栏 | 说明 |
| --- | --- | --- |
| `< md`（< 768px） | **56px 图标栏** | 只留 mark / 导航图标 / 状态点，文案全隐；演示提示与端点行隐藏 |
| `≥ md` | **260px 全宽侧栏** | 图标 + 文案、品牌名、网关状态两行 |

为什么收成图标栏而不是直接隐藏：直接隐藏会丢掉导航与状态，收成 56px 既保留两者又不牺牲主区。
实测 480px 下固定 260px 会把主区挤到 ~200px —— 端点 URL 逐字换行、账号卡名称被截断
（「塞西莉亚4412」→「塞西...」），完全不可用。

其余适配点：

- **接入盒**：端点行窄屏**堆叠**（标签在上、值独占一行）—— 宽屏标签固定 96px，
  窄屏会把值列压到几像素导致 URL 逐字换行。
- **模型表**：`overflow-x-auto` 滚动容器 + `min-w-[440px]`，放不下时横向滚动；
  附加三列（最大上下文 / 输出上限 / 思考模式）在 `< md` 隐藏。
- **登录弹窗**：左栏（渠道 + 步骤概览）窄屏**堆叠**到顶部并改成横排 ——
  固定 224px 在 480px 下会把右侧流程挤到 ~200px。
- **统计条 / 总览条 / 工具条**：一律 `flex-wrap`，窄屏自然折行。

### 账号池页的排布

渠道卡用 **两列网格**（`lg:grid-cols-2` + `items-start`）：卡顶成行对齐，短卡不在单元格内被拉伸。
三列时单卡仅约 380px，中文账号名与额度条会互相挤压（实测「塞西莉亚4412」被截断）。

- 深色是**唯一主题**，不留浅色分支与切换入口。
- 授权链接 / 登录进度只在**登录弹窗**内渲染（遮罩与 ESC 不关），不出现在其他页面。
- 登录弹窗三种形态，由 `state` 决定：
  - **两步登录**（`login_input` 非空，如 loomy 短信验证码）→ **只渲染一个三行表单**，
    不摆授权步骤时间线：
    `手机号（+86）` 输入框 / `验证码` 输入框（左）+ `获取验证码`（右）/ `登录`（左）+ `取消`（右）。
    后端仍是两次顺序的 `requestInput`（先要手机号 → 发码 → 再要验证码），表单把它映射成三行：
    手机号那一步「获取验证码」可点、验证码框与「登录」禁用；码发下来后二者解禁、
    按钮转「已发送」。两个输入的值挂在**弹窗**上（后端换一次输入请求就重渲染，
    挂在子组件上会被清掉）；
  - **扫码**（`qr_url`）→ 二维码 + 确认步骤；
  - **授权链接**（`auth_url`）→ 复制链接 + 官方页完成 + 自动回调，**三步**。
    第四步「手动粘贴回调链接」已删：控制台与网关同机，回调必然到得了本机端口，
    粘贴框对 Web 端是纯冗余（CLI 仍保留 `pasteCallback` 兜底）。
- **准备期画骨架**：弹窗挂载到「本轮第一个状态更新到达」之间只显示骨架，
  绝不渲染上一轮残留的 `done` / `error` / 旧授权链接。
  后端 `triggerLogin` 也会**同步**清空旧状态（`beginLogin()`），
  两边一起才封得住那个最长 3 秒的窗口（2026-10-26 主人反馈「一开始就显示登录成功」）。
- **登录成功后弹窗自动关闭**：页面轮询 `/web/api/state`，一旦 `ui_state` 变成 `done`，
  立刻关闭弹窗、刷新账号池 / 登录态 / 账本，并主动重查该渠道额度（新账号额度与旧账号不同）。
  判据要求先观察到 `login` / `error` 等中间态，避免上一次登录残留的 `done` 误关新弹窗。

## 账号展示与额度

- 渠道头**只显示小写 cid**（如 `catpaw`），不显示展示名与 `ok` 文字；状态只用小圆点。
- 账号主标识**渠道给什么就显示什么**，前端不做脱敏：取用顺序
  `name`（渠道给的可读标识：nickname / 用户名 / 邮箱 / 手机号）→ `label` → `uid` → `key`，
  取到即原样渲染。
  ⚠ 2026-10-26 主人决定**去掉脱敏设计**：此前前端会把「没有 name」的账号统一打码
  （`138****0001`、`UID 100****042`），理由是看板可能被投屏、截图分享；但那让同一页面
  出现两套口径 —— astudio 给的是明文手机号、lobsterai 上游只给打码手机号，看起来自相矛盾。
  **要不要脱敏由渠道/上游决定**（拿不到明文就别存），前端不再统一加工。
  实测同一页：astudio `13146069411`（明文）、lobsterai `131******11`（上游只给密文）。
- 额度**按账号**查询：后端用每个账号自己的凭证调用
  `billing.fetchCredits({ credential, refreshOn401: false })`，结果写进账本
  `accounts[key].credits`；卡片里额度条**独占一行**，只显示数值与百分比
  （**不显示「积分」「credits」这类单位**），数值带千分位、最多 2 位小数。
- 百分比以**当前额度窗口内第一次账单**为 100% 基线（实现见 `pool-usage.ts` 的 `pickBaseline`）：
  窗口键取渠道声明的 `quotaPeriod().resets_at`，没声明才回落本地日期；窗口滚动或同一窗口内
  `remain` 回升（奖励到账）时重设基线。**没有基线或 `remain` 不可用时不显示百分比** ——
  不回退上游 `remain_percent`（它是窗口占比，常年 100，会给出误导性的满格）。
  也不用上游 `size` 当分母（各渠道口径不一）。
- 查询失败显示「额度查询失败」，不把未知显示成 0。

### 交互铁律：**不要 hover 悬浮气泡**

**禁止**任何「鼠标悬停才出现」的**信息**浮层 / 气泡 / 提示：

- 不用原生 `title=` 属性（浏览器会弹原生 tooltip），也不用自建的 hover popover；
- 信息要么**直接可见**（写进卡片正文，允许换行、不裁切），要么放进**点击后**才出现的
  详情区（弹窗 / 抽屉 / 展开行）；
- 按钮的无障碍名称用 `aria-label`（**不产生**任何可见气泡），不要用 `title` 兼职；
- 原因：截图、投屏、触屏与键盘操作都拿不到 hover 内容，悬停提示等于让信息只对
  「正在用鼠标悬停的人」可见 —— 关键信息不能依赖它。

⚠ 这条只管**信息**，不管**低频动作按钮**：账号行上的切换 / 删除默认 `opacity-0`、
`group-hover` 才出现（`group-focus-within` 保键盘可达，`pointer-coarse` 触屏常显）。
信息一个都不能藏，动作可以 —— 动作藏了只是少一条捷径，信息藏了等于没有。

### 登录链接：**复制，不弹新窗口**

「添加账号」弹窗里的授权链接，点击只做**复制到剪贴板**（剪贴板不可用时静默失败，
用户仍可手动复制下方那一行），**不调 `window.open`、不用 `target="_blank"`** ——
由用户自己决定在哪个浏览器 / 窗口打开。页面里不应出现「点授权链接 → 自动开新标签页」。

⚠ 「添加账号」是**强制重新授权**（后端 `force`），但**不会先删掉现有凭据**：
授权要等人操作，期间旧凭据继续可用；只有新凭据落盘（原子覆盖）才替换它。
（旧实现先删凭据，授权没走完渠道就掉线，界面出现「未登录 + 账号生效中」的矛盾状态。）

### 不可逆操作：**二次确认**

删除账号（`onRemove`）不可逆（**生效账号会同时登出**），必须先确认：点垃圾桶弹出
`ConfirmDialog`（标题「删除账号」+ 渠道 / 账号名 + 「取消 / 删除账号」），只有点
「删除账号」才真调 `onRemove`。规则：

- 弹窗**挂到 `document.body`**（`createPortal`）：账号卡带 `@container`，它隐含
  `contain: layout`，会成为 `fixed` 后代的包含块，不 portal 就会被卡片裁切；
- 同一时刻只允许一个账号处于待确认态；
- 切换账号、开始删除（`busyKey !== null`）时清空确认态；
- 点遮罩 / 按 ESC / 点「取消」都是取消，不产生任何副作用；默认焦点在「取消」上。

### 「解除」按钮：常显，不藏 hover、不做二次确认

异常（`error`，连败熔断）与冷却（`cooldown`，额度耗尽）的账号行上有一个**常显**的
「解除」按钮 —— 调 `resetAccount`，后端清零连败、清掉冷却标记并恢复 `ok`
（语义见 [POOL-ARCHITECTURE.md](./POOL-ARCHITECTURE.md) §2.4「额度耗尽 → 账号冷却」）。

- **不藏在 hover 动作区里**：切换 / 删除是低频动作，藏起来没问题；「解除」是这类账号
  唯一的出路（熔断后路由会一直跳过它），触屏与键盘也必须点得到。
- **不做二次确认**：非破坏性 —— 清标记只是让它重新参与路由，失败了还会再被标回来。
- 后端拒绝的情况（`unauthorized` 需重登 / 账号不在池里）**如实显示错误文案**，不假装成功。

## 技术栈与构建

- React 19 + TypeScript + Vite 8（`base=/web/`）+ Tailwind CSS v4 + TanStack Query v5 +
  react-router v8 + lucide-react 图标 + **Radix UI（headless 原语）**。
- **Radix 用在哪**（2026-10-26 引入）：`@radix-ui/react-toast`（轻提示）、
  `@radix-ui/react-dialog`（登录弹窗）、`@radix-ui/react-alert-dialog`（删除确认）。
  选它的理由是 **headless** —— 只给行为（焦点陷阱、焦点归还、滚动锁、aria 接线），
  不给视觉，所以控制台的 Codex 近黑单色风格完全由 Tailwind 令牌决定，没被组件库带跑。
  （antd / MUI 自带一整套设计系统，引进来要么覆盖它、要么推翻现有设计。）
- **`packages/ui` 不受依赖白名单约束**：`scripts/verify-contract.mjs` 的 `DEP_ALLOW`
  只管渠道包与 `packages/cli`；UI 包本来就有 6 个第三方包（React 全家桶 + Tailwind + Vite + lucide）。
- `npm run build` 顺序：`tsc -b` → `vite build packages/ui` → cli bundle →
  `scripts/copy-ui.mjs` 把产物拷到 `packages/core/gateway/dist/ui` 与 `packages/cli/dist/ui`
  （**少拷一份，全局 `mx web` 就报「UI 未构建」**）。

### 静态资源落点：必须走 `src/assets/`，不要放 `public/`

页面图标在 `packages/ui/src/assets/favicon.svg`，由 `index.html` 以 `/src/assets/favicon.svg`
引用。Vite 会把它打进 `assets/` 并加内容哈希（产物形如 `/web/assets/favicon-<hash>.svg`）。

**为什么不能放 `public/`**：console handler 只托管两个静态位置 —— 前缀根 `/web/`（返回
`index.html`）与 `/web/assets/*`；其余 GET 一律走 SPA 回退（`console.ts` 的
`serveStatic(res, WEB_UI_INDEX)`）。放 `public/` 的 `/web/favicon.svg` 会被回退成 HTML
而拿不到 SVG。同理，图标不要声明成 `/web/favicon.svg` 这类前缀根路径。

在 `index.html` 里显式声明 `<link rel="icon" type="image/svg+xml" href="/src/assets/favicon.svg">`
还有第二个作用：浏览器不再去要默认的 `/favicon.ico` —— 那个路径在网关根下不存在，
会以 `not_found` 写进 `access/<date>/failure.log`，属纯噪音。

## 数据通道

- `GET /web/api/state`：登录快照（ui_state / message / auth_url / qr_url / **login_input** / 端点），
  外加模型池视图所需的 `models` / `model_info` / `channel_caps`（各渠道能力位）。
  - `login_input` 非空 = 渠道在等用户输入（两步登录，如 loomy 的短信验证码）。
    界面据此把登录弹窗切成**输入卡**；`null` = 没有待回答的输入。
- `POST /web/api/commands`：动作分发（login / status / **models** / billing / accounts /
  activateAccount / **resetAccount** / removeAccount / syncPool / pasteCallback /
  **submitInput** / **cancelInput**）。
  - `billing` 支持 `args.refresh: true`（真实重查各渠道账单）与 `cid` 过滤（单渠道刷新）。
  - `resetAccount`：解除 `error` / `cooldown` 标记（不动凭证）；`unauthorized` 会被拒绝并给出原因。
  - `pasteCallback`：手工兜底通道，把用户粘回的回调链接喂给等待中的登录流程。
    raccoon 等授权码渠道现在优先走**本地 HTTP 回调自动完成**，Web UI 已不提供粘贴入口
    （控制台与网关同机，回调必然到得了本机端口）；该动作保留给 CLI 与非本机场景。
  - `submitInput`：把两步登录的输入交回给等待中的渠道；`cancelInput`：弹窗关闭时调用，
    让等待输入的渠道立刻收尾（不调用会挂到 10 分钟超时）。
- `GET /web/api/logs`：访问日志查询（只读）。参数 `date` / `outcome` / `cid` / `model` /
  `stream` / `slow` / `q` / `limit`（上限 500，默认 100）/ `offset`。
  返回实际日期（当天无日志时后端回落到最新日期）、可选日期与渠道、`stats`（基于**未过滤**读窗口的
  当天概览）、`total`（命中筛选数）、`entries`。
  - 读窗口有界：每个 outcome 文件只读尾部 1MB、总扫描 2 万行；超出时 `truncated=true`，
    界面据此把统计标注成「只覆盖最近 N 条」，而不是假装是全量。
  - 只读 `success` / `failure` / `other` 三个分桶 —— `slow.log` 是它们的并行副本，
    一起读会让慢请求在列表里出现两遍。
- `GET /web/api/logs/payload`：按 `id`（+ 可选 `date`）读回请求正文抓取记录，
  返回 `records`（`phase=client` 的客户端原样体 + `phase=upstream` 的各次上行体）。
  恒开启：正文抓取不可关闭（见 [LOGGING.md](./LOGGING.md) §9）。
- 这两个端点**带同源校验**（与 `POST /api/commands` 同款）：日志含模型名与请求路径，
  比 `/api/state` 更不该被跨源页面读到；无 `Origin` 头时放行，curl / 脚本不受影响。
- `POST /web/api/theme`：切主题；`POST /web/api/retry-login`：重试登录。
  两者在 `console.ts` 里已实现，但当前 UI **没有入口**（深色是唯一主题，也没有重试登录按钮）——
  前端 `lib/api.ts` 里的 `setTheme` / `retryLogin` 只是保留的调用面。
- `GET /web/api/overview`：仪表盘聚合视图（一次拉全）。返回当日 KPI
  （`usage`：请求/成功/失败/慢/平均耗时/tokens）、每渠道状态（`channels`：模型数 +
  账号健康分布 + 今日成败）、模型池概览（`model_pool`：总数/免费/多模态/思考）、
  最近 5 条请求（`recent`：时间/模型/结果/耗时/tokens）。带同源校验，5 秒轮询。
- `/api/commands` 返回值由前端 `lib/api.ts` 统一**解包 `data`** —— 页面不要再取一层
  `.data`（双重解包会导致 tab 崩溃）。

## 账本维度

账本主维度是**渠道**（used / 冷却 / billing_at），另按**生效账号**拆分 ok / fail 计数
（`ChannelLedger.accounts[key]`），控制台账号池卡片按「渠道 × 账号」展示；
账本数字记在请求发生时的当前生效账号头上。

## 演示模式（在线演示 + 本地静态构建）

控制台的**演示构建**（`DEMO=1`）用一份**虚构数据**在浏览器里跑完整交互流程，
不需要起网关、不碰任何真实账号。

> **在线演示：<https://bluechonk.github.io/modelmux/>**（GitHub Pages，只发布演示构建）。
> 真实控制台仍是**本机工具**（要读本机网关与账号池），不上公网 —— 看真机就 `mx web` ✓。

### 发布（GitHub Pages）

`.github/workflows/demo-pages.yml`：push 到 `main`（命中 `packages/ui/**` / 依赖清单 /
workflow 自身）或手动 `workflow_dispatch` 时，`npm ci` → 构建演示包 → 部署到 Pages。

两个**必须**记住的点（改 workflow 或 `vite.config.ts` 前先读）：

| 点 | 为什么 |
| --- | --- |
| `DEMO_BASE=/<repo>/` | Pages 的**项目站点**挂在 `https://<owner>.github.io/<repo>/` 下。资源若用根路径 `/assets/…` 会 404、整页空白。构建时把前缀传给 `vite.config.ts`，`base` 与 `App.tsx` 的 `basename` 都从 `__DEMO_BASE__` 推导（两处各写一份必然漂移）。用户站点（`<owner>.github.io`）前缀是 `/`，workflow 里按仓库名判断。 |
| `cp dist/index.html dist/404.html` | 纯静态托管没有 SPA 回退：直接访问 `/accounts` 会 404。Pages 用 `404.html` 兜底，客户端路由再把页面画出来（**状态码仍是 404，但页面正常渲染**；入口 `/` 是 200）。 |

Pages 的源设为 **GitHub Actions**（`build_type: workflow`），不是 gh-pages 分支 ——
产物由 `upload-pages-artifact` 直接交给 Pages，仓库里不留构建产物。

### 为什么需要「演示构建」

真实控制台每个页面都要 `fetch('/web/api/*')` 读本机网关；演示构建把这层换成内存实现，
于是**任何静态托管**（甚至直接双击 `dist/index.html`）都能看界面与点流程 ✓。

### 实现

| 位置 | 作用 |
| --- | --- |
| `src/lib/demo.ts` | 虚构数据源 + 内存状态机（渠道/模型/账号池/账本 + 登录流程） |
| `src/lib/api.ts` | `IS_DEMO` 为真时用内存实现替换所有 fetch |
| `vite.config.ts` | `DEMO=1` 时切换 base（`DEMO_BASE`）并注入 `__DEMO_MODE__` / `__DEMO_BASE__` |
| `src/App.tsx` | `basename` 从同一个 `__DEMO_BASE__` 推导 |
| `src/env.d.ts` | 两个注入常量的类型声明 |
