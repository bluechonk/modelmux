# Web 控制台（mx web）

`mx web` 把 React 管理看板挂在网关的**唯一端口**上（`http://127.0.0.1:4412/web/`，
控制台 API 在 `/web/api/*`），没有独立进程与独立端口。

## 设计系统（`packages/ui/src/index.css`）

视觉语言参照 **Codex / ChatGPT**：**纯近黑单色系**。顶部导航比内容区更深、浮层比内容区更浅，
层级只靠底色差与留白表达；**accent 就是白**（主按钮白底黑字、选中态白色高亮），
不用任何彩色品牌色；状态语义色保留但饱和度压低，只出现在「需要人看」的地方。

UI 的配色、层级与圆角**只在 `index.css` 的 `@theme` 里定义一次**，组件一律用令牌类，
不直接写 `gray-900` / `sky-500` 这类原始色 —— 换主题只改这一处。

| 组 | 令牌类 | 用途 |
| --- | --- | --- |
| 表面（四个深度层） | `bg-surface` `#171717` / `bg-canvas` `#212121` / `bg-raised` `#2f2f2f` / `bg-overlay` `#3a3a3a` | 顶部导航（最深）→ 内容区 → 卡片与输入盒 → 悬浮层与选中底 |
| 描边 | `border-line` `#383838` / `border-line-strong` `#4d4d4d` | 几乎不用；需要分块时才出现，且刻意看不清 |
| 文字 | `text-ink` `#ececec` / `text-ink-soft` `#b4b4b4` / `text-ink-faint` `#8e8e8e` | 主 / 次 / 弱 |
| 语义 | `brand` **`#ffffff`** / `free` / `warn` / `danger` | **accent = 白**：主按钮是白底黑字（`text-[#171717]`），不是彩色底 |

三个组件类与一处动效：

| 类 | 用途 |
| --- | --- |
| `.panel` | 唯一的容器形态（`rounded-2xl border border-line bg-raised`），端点盒、渠道卡共用 |
| `.panel-title` | 面板标题（图标 + 文字，14px 常规字重 —— 不靠加粗靠留白） |
| `.pill` | 徽标（状态 / 计数）；**语义类按状态着色**（正常绿 / 冷却黄 / 异常·没钱红，底色 12% 透明），纯计数类用中性底 |
| `.nav-item` | 顶部标签导航项（纯文本 + 圆角 hover 底；选中态 `bg-raised`，不用彩色底） |
| `.live-dot` | 网关状态灯的呼吸动效（`prefers-reduced-motion` 下自动关闭） |

约定：

- 圆角只有两档：容器 `rounded-2xl`、行内元素 `rounded-lg`；主按钮 `rounded-full`。
- **单色系**：除状态语义色（免费/冷却/错误）外不出现任何彩色；
  主操作按钮一律 `bg-brand text-[#171717]`（白底黑字）。
- 标题是**无衬线常规字重**（ChatGPT 的标题不靠加粗靠留白），不用衬线字体。
- 数字用等宽数位（`.tabular`），统计值变化时不抖动。
- 键盘可达：`:focus-visible` 有统一聚焦环（鼠标点击不显示）。
- 图标统一用 `lucide-react`，尺寸三档：12（小徽标）/ 14（行内）/ 16（面板标题）。
- **品牌 mark 是内联组件**（`components/BrandMark.tsx`，极简鲸鱼剪影 +
  分叉尾鳍 = 多条渠道，单色、16px 清晰），与 `assets/favicon.svg` 同形（白色）；
  颜色跟随 `className` 的 `text-*` 令牌（顶部导航用 `text-ink`）。

入·出，数值列右对齐；分页条 sticky 跟随视口底部，**只放上一页 / 页码 / 下一页**）。点行**展开**元数据详情（request id 可复制、method+path、三段耗时、请求规模、错误码与说明、usage）；**最右侧「上下文」按钮**弹窗展示整段 message 对话（系统提示词 / 用户 / 工具调用与命令 / 工具定义逐条渲染，**AI 回复按 Markdown ×**：点遮罩与 Esc 都不关（正文可达 MB 级，误触的代价是丢掉阅读位置；键盘用户 Tab 到 × 回车即可）。**右侧悬浮「回到顶部 / 滚动到底部」两枚圆钮**：仅当内容超出可视区才出现，到顶 / 到底各自置灰（不隐藏 —— 隐藏会让另一枚钮在指针底下消失），点击平滑滚动（`prefers-reduced-motion` 时瞬时）；滚动区右侧留 64px 栏位，按钮不压正文（也不放右下角 —— 那里是 toast 的地盘）。**滚动位置按 request id 记忆**：`localStorage` 键 `modelmux.logs.ctx-scroll:<request id>`，停滚 400ms 落盘（关弹窗前会把待落盘的位置冲刷掉）、点圆钮立即落盘，重开同一请求自动回到原位（恢复不播动画；滚轮 / 触摸 / 滚动键 / 拖滚动条会接管并放弃恢复）。记录集签名变化（payload 日志按 10MB 轮转、保留期清理、重试新增 attempt）或超过 14 天（= access 保留期）即作废旧位置、回退置顶；存储不可用只是不记忆，界面无任何提示。**窄屏（< 768px）砍掉「上下文」列，入口挪进展开行**（「查看请求上下文」按钮）—— 固定列合计已超表格最小宽，再加列会把模型列挤成零宽。**正文按需分片、两头起手**：打开时只拉元数据（几百字节）+ **头片**（开头 64 KiB）+ **尾片**（末尾一格），所以「回到顶部 / 滚动到底部」从第一次点击起就落在**真正的两端**；中间的空格子由空隙块两侧的哨兵补 —— 向下滚补前半段、向上滚补后半段（方向门：手指/滚轮往哪边走就补哪边，避免停在空隙上把整份正文一次拉完）。格子固定 64 KiB 且**按格对齐**：任意两个窗口要么同一格、要么不相交，两端并发取回也不会拼出重复段；只剩一格时两头会各取一次同一格（重复数据在拼接时去重）—— 换成「让某一侧认领」，反方向滚动时那一格就永远不来。**接缝痕迹**：格子按字节切，切点落在多字节字符中间时那个字符在接缝处变成替换符（实测 2.77 MB 正文 44 片、3 处；服务端分片读法如此，见 [LOGGING.md](./LOGGING.md) §9）—— 拼装结果与整段取回逐字一致，只差这几处；接缝位置不遮挡阅读、也不影响复制（复制走「复制完整 JSON」直接按需取全文）。**未取全时**头片走消息卡片、尾片按**未解析原文**呈现（真机数据：末尾区域是最后一条消息的正文尾部 + `]` + 顶层参数 + 一大段 `tools[]` 定义，字节切点还落在字符串中间，消息边界既不在片头、数量也只有一两条 —— 套卡片要写一套后缀抢救解析，收益极低）；**两头接上后**自动重排成与整段解析完全一致的卡片视图（实测 426.5 KB 正文：拼装结果解析出的消息数与整段一次取回完全相同）。头片贴底时还会**跟随补片**：尾片是往尾巴前面补的，补进来会让末尾下移，贴底状态会跟着贴回末尾，避免点完「到底」又被推走。整段正文解压后可达 MB 级（实测单条 3.5 MB 压缩 → 9.4 MB 明文），一次性传输会把弹窗拖到秒级。**消息拆分对截断前缀同样生效**：分片正文不是合法 JSON，`parseLenient`（`lib/lenient-json.ts`）把前缀里**已完整闭合**的消息抢救成卡片、并剥离一层「字符串内嵌 JSON」的渠道信封（零渠道知识），新片到达时新消息随之追加；真解不开的（qodercn 编码体、catpaw 自有字段）才整段原文呈现并说明。5 秒轮询，展开、翻页或弹窗打开时暂停 |

> `/api/logs` 也就能用 —— 而排查异常恰恰最需要看日志。`down`（网关真不在）与状态查询失败时

### 为什么仪表盘首屏是「接入盒」

参照 ChatGPT 的首屏：一块大的圆角输入盒占据视觉中心，周围留白。
这里最高频的动作是**把 base_url 抄走**，所以端点做成首屏主体、统计压成一行内联数据。

### 为什么账号卡有最小宽度

单卡低于约 340px 时，中文账号名与额度条互相挤压（实测「塞西莉亚4412」被截断），
故轨道取 `minmax(min(340px, 100%), 1fr)`：**列数跟着容器走**（1400px 下 3 列），
`min(340px, 100%)` 是窄屏收口 —— 视口比 340px 还窄时不把容器顶出横向滚动。

### 账号卡的布局统一（默认 1 个账号位 + 单行扁平 + 折叠）

多账号、多状态容易把页面撑得参差。定稿的规则是「只露 1 个 + 卡底条恒渲染」：

1. **每卡默认只露 1 个账号** —— 生效账号恒排首位，所以露出的就是最该看的那行；
   **卡底条恒渲染**，四态各一句话：
   - 0 个账号 → 铺**一个空位行**占位 + 卡底「暂无账号」
   - 1 个账号 → 1 行 + 卡底「已展示全部」
   - N 个账号（折叠）→ 1 行 + 卡底可点条「展开剩余 N-1 个账号」
   - N 个账号（已展开）→ 全部铺开 + 卡底可点条「**收起**」——动作写在**左下角**
     （与「展开」同一位置，手不用在卡里左右找；收起放右下角是错位的）

   实测（1440 视口，演示数据含 0 / 1 / 5 个账号三种渠道）：**三种卡高全部 164px**，
   空池靠占位行与别的卡等高 —— 账号池是横向等高的卡片列，缺一行就整片参差。

   为什么不全铺开：渠道池动辄 4-6 个账号，铺满会把「同屏能看几个渠道」压到 1-2 个，
   而账号池页先要回答的是「这个渠道还能不能用」。
2. **展开态整卡跨满一行 + 账号恒一列**（`col-span-full`）：网格行高取行内最高的卡，
   展开的卡会把同行两个单账号卡下方各留 207px 空白（实测行高 `[371,164,164,164]`）——
   让展开的卡独占一行、其余卡片顺延，结构上不再有空洞。
   展开后账号**一行一个竖向排开**（不铺两列）：两列会把每行压成半宽、账号名与进度条互相挤，
   读序也会变成「左右左右」。
3. **账号行恒定单行 44px（`h-11`）**：状态点 / 名称 / 状态 pill（正常、冷却、没钱…）
   / **额度进度条 + 百分比** / 操作，全部横向排开。
   剩余额度、今日消耗、今日 tokens、今日首次账单、冷却倒计时、熔断连败、凭据失效原因
   **全部收进进度条的悬停面板**（行内只留「还剩几成」，一眼读完）。
   - 进度条口径：**今日首次账单**（`baseline.remain`）为 100%，当前 `remain` 占它的比例；
     0–100%，耗尽染红、<10% 染黄、其余绿。
   - 面板：悬停 / 聚焦显示，点击可**固定**（触屏没有悬停），点外部或 Esc 关闭；
     portal 到 `document.body`（卡根节点 `overflow-hidden`，不 portal 会被卡底裁掉），
     实测自身尺寸后钳制在视口内、贴下缘自动翻到进度条上方。
   - 面板配色跟卡片层级走：`bg-overlay`（比卡片 `bg-raised` 高一档）+ `line-strong` 描边，
     不用近黑色 —— 近黑浮层在深色主题里像另一个应用。
5. **切换 / 删除默认隐藏**，鼠标移到该账号行才出现（`group-hover`）；
   `group-focus-within` 保证键盘可达，`pointer-coarse`（触屏）常显。
   删除走**确认弹窗**（见下文「不可逆操作」）。

### 模型清单（仪表盘内联，`pages/Dashboard.tsx`）

**为什么不再有独立的模型列表页**：对外模型只有 deepseek 家族几个名字，一页专门列表收益太低；
而「这个模型现在能不能用、快不快」是仪表盘首屏就该回答的问题，所以内联进仪表盘右列。

| 元素 | 形态 |
| --- | --- |
| 行内容 | 模型名（等宽，deepseek 裸名）+ **健康度标签**（排队 / 异常 / 慢；无调用记录不挂标签，紧跟模型名）+ **平均 TPS**（近 7 天成功请求均值，算不出显示 `-`）+ **输入模态图标**（`T` = 文本恒有；`+` 图片图标 = 支持图片） |
| 模态口径 | 同一模型的不同渠道能力不同（如 `deepseek-v4-flash`：astudio 只收文本、workbuddy 收图片），行内取**并集**—— 答的是「这个模型能不能收图」，与「候选渠道有哪些」同一层级；逐渠道能力看 `GET /web/api/state` 的 `models[].meta.inputModalities` |
| 健康度口径 | 与 `lib/model-health.ts` 同源（`classifyModel`）：优先级 排队 > 异常 > 慢，一行只出一个；**无调用记录不挂标签**（没数据 ≠ 不可用） |
| 数据来源 | 模型名与元数据来自 `GET /web/api/state` 的 `models`（`{model, cid, meta}`，按模型去重）；健康度来自 `GET /web/api/usage?range=7d` 的 `models[]`，**按模型合并各渠道**（ok/fail/queued 累加、TPS 取均值）—— 仪表盘不显示渠道，落点由网关按额度自动挑 |

- **不显示渠道**：仪表盘回答的是「这个模型能不能用、快不快」；「是哪家渠道在出」属于网关的调度细节，
  要看去请求日志（`GET /web/api/logs` 的 `cid` 列）。
- 内联后不再有搜索 / 筛选 / ping / 复制等工具条 —— 模型数只有个位数，这些控件是给几十上百个模型准备的。

### 响应式适配（「被挤压时做好适配」）

导航在**顶部**（`components/LayoutSingle.tsx`），不再有固定宽的侧栏：

| 断点 | 顶部导航 | 说明 |
| --- | --- | --- |
| `< md`（< 768px） | **品牌 mark + 纯图标 Tabs + 网关状态** | 四个标签 + 品牌 + 网关状态在 390px 下要 678px，横向滚动又没有任何提示：实测用户只看到被切掉半个字的「账」，还以为「请求日志」这个页面不存在。故窄屏只留图标（`aria-label` 保留可读名），四个图标 40px 一个，396px 视口起就够放；品牌名 `≥ 420px` 才显示 |
| `≥ md` | **品牌 + 图标 + 标签 + 网关状态** | 全部入口一屏可见 |

内容区是**单列纵向流**（`max-w-[1400px]` 居中，页面级滚动）：窄屏不再需要抽屉/遮罩，
区块自上而下堆叠、超出即自然撑开。滚动发生在 `LayoutSingle` 的 `<main>`（`overflow-auto`），
头部常驻；右下角有**「回到顶部」悬浮按钮**（`BackToTop`）：滚动超过 320px 淡入
（`bg-overlay/85 + backdrop-blur`，桌面 40px / 触屏 44px），点击平滑回顶，回顶自动隐藏；
右下角 toast（z-60）出现时会短暂盖住它（z-40），消失后自动露出。

其余适配点：

- **接入盒**：端点行窄屏**堆叠**（标签在上、值独占一行）—— 宽屏标签固定 96px，
  窄屏会把值列压到几像素导致 URL 逐字换行。
- **模型表 / 日志表**：最小宽 `< md` 取 300px（只留核心列，360 宽一次看全）、
  `≥ md` 日志表取 **960px**（9 个固定列合计 780px，模型列保底 180px ——
  表格最小宽若等于固定列之和，模型列会被压成 0、模型名逐字符竖排（2026-11-05 实测行高 321px）；
  放不下就横向滚动，并由 `ScrollFade` 在右缘铺 32px 渐隐**提示还有列**。
  **列的取舍必须靠「少渲染 `<td>`」，不能用 `hidden md:table-cell`** ——
  `display: none` 的 `<td>`/`<col>` 在 `table-layout: fixed` 下**仍占列槽位**：
  实测（390 视口）模型列只拿到 48px，而表头那行按自己的算法拿到 238px，**表头与表体还会错位**。
  故由 `matchMedia('(max-width: 767px)')` 与 Tailwind `md` 同口径地判窄屏，再用**同一份
  列定义**驱动 `<colgroup>` / `<th>` / `<td>`，保证三者恒等。
- **日志页「上下文」入口在窄屏挪进展开行**：窄屏固定列（时间 88 + 结果 104 + 上下文 88）
  合计 280px，表格最小宽 300px 下模型列只剩 ~20px，长模型名无法阅读 —— 正文可读性优先，
  故砍列（`context` 标 `wide`），按钮放进详情行（实测 390 下 130×44px，触控达标）。
  窄屏同样砍掉 `toggle` 列，展开靠点行本身，不丢功能。
- **触控目标**：`.tap` / `.tap-square` 只在 `< md` 生效，把可交互元素垫到 ≥ 2.75rem
  （WCAG 2.5.5 的 44px）。`min-height/min-width` 天然压过既有的 `h-*`/`w-*`，
  所以直接加在定尺寸按钮上即可。`≥ md` 不限 —— 桌面是鼠标，放大只会白白牺牲信息密度。
- **字号下限 12px**：徽标 `.pill` 与所有 10/11px 文本统一到 12px。
- **账号卡**：窄屏只保留**剩余额度数值**（标签、「今日消耗」「今日 tokens」按卡片宽度逐级恢复）——
  一行装不下「标识 + 状态 + 额度 + 两个 44px 操作键」时，先保「还剩多少」。
- **登录弹窗**：左栏（渠道 + 步骤概览）窄屏**堆叠**到顶部并改成横排 ——
  固定 224px 在 480px 下会把右侧流程挤到 ~200px。
- **统计条 / 总览条 / 工具条**：一律 `flex-wrap`；账号池总览条按 **chip** 分组
  （中性底 + 圆角 + `whitespace-nowrap`），折行后逐行对齐，标签与数字同处一个视觉单元。

360 与 390 下三页**触控 < 44px = 0、字号 < 12px = 0、`title` 属性 = 0、页面级横向溢出 = false**，

### 账号池页的排布

渠道卡用 **两列网格**（`lg:grid-cols-2` + `items-start`）：卡顶成行对齐，短卡不在单元格内被拉伸。
三列时单卡仅约 380px，中文账号名与额度条会互相挤压（实测「塞西莉亚4412」被截断）。

- 深色是**唯一主题**，不留浅色分支与切换入口。
- 授权链接 / 登录进度只在**登录弹窗**内渲染（遮罩与 ESC 不关），不出现在其他页面。
- 登录弹窗三种形态，由 `state` 决定：
  - **两步登录**（`login_input` 非空，如 loomy 短信验证码）→ **只渲染一个三行表单**，
    不摆授权步骤时间线：
    `手机号（+86）` 输入框 / `验证码` 输入框（左）+ `获取验证码`（右）/ `登录`（左）+ `取消`（右）。
    后端仍是两次顺序的 `requestInput`（先要手机号 → 发码 → 再要验证码），表单把它映射成三行：
    手机号那一步「获取验证码」可点、验证码框与「登录」禁用；码发下来后二者解禁、
    按钮转「已发送」。两个输入的值挂在**弹窗**上（后端换一次输入请求就重渲染，
    挂在子组件上会被清掉）；
  - **扫码**（`qr_url`）→ 二维码 + 确认步骤；
  - **授权链接**（`auth_url`）→ 复制链接 + 官方页完成 + 自动回调，**三步**。
    第四步「手动粘贴回调链接」已删：控制台与网关同机，回调必然到得了本机端口，
    粘贴框对 Web 端是纯冗余（CLI 仍保留 `pasteCallback` 兜底）。
- **准备期画骨架**：弹窗挂载到「本轮第一个状态更新到达」之间只显示骨架，
  绝不渲染上一轮残留的 `done` / `error` / 旧授权链接。
  后端 `triggerLogin` 也会**同步**清空旧状态（`beginLogin()`），
  两边一起才封得住那个最长 3 秒的窗口（2026-10-26 主人反馈「一开始就显示登录成功」）。
- **登录成功后弹窗自动关闭**：页面轮询 `/web/api/state`，一旦 `ui_state` 变成 `done`，
  立刻关闭弹窗、刷新账号池 / 登录态 / 账本，并主动重查该渠道额度（新账号额度与旧账号不同）。
  判据要求先观察到 `login` / `error` 等中间态，避免上一次登录残留的 `done` 误关新弹窗。

## 账号展示与额度

- 渠道头**只显示小写 cid**（如 `catpaw`），不显示展示名与 `ok` 文字；状态只用小圆点。
- 账号主标识**渠道给什么就显示什么**，前端不做脱敏：取用顺序
  `name`（渠道给的可读标识：nickname / 用户名 / 邮箱 / 手机号）→ `label` → `uid` → `key`，
  取到即原样渲染。
  **要不要脱敏由渠道/上游决定**（拿不到明文就别存），前端不再统一加工 ——
  前端统一打码会让同一页面出现两套口径：astudio 给的是明文手机号、lobsterai 上游只给打码手机号，
  看起来自相矛盾。实测同一页：astudio `13800138000`（明文）、lobsterai `131******11`（上游只给密文）。
- 额度**按账号**查询：后端用每个账号自己的凭证调用
  `billing.fetchCredits({ credential, refreshOn401: false })`，结果写进账本
  `accounts[key].credits`；账号行右侧显示**剩余额度数值**（带千分位、最多 2 位小数，
  **不显示「积分」「credits」这类单位**），卡片够宽时再恢复「剩余额度」标签与「今日消耗」。
- 百分比以**当前额度窗口内第一次账单**为 100% 基线（实现见 `pool-usage.ts` 的 `pickBaseline`）：
  窗口键取渠道声明的 `quotaPeriod().resets_at`，没声明才回落本地日期；窗口滚动或同一窗口内
  `remain` 回升（奖励到账）时重设基线。**没有基线或 `remain` 不可用时不显示百分比** ——
  不回退上游 `remain_percent`（它是窗口占比，常年 100，会给出误导性的满格）。
  也不用上游 `size` 当分母（各渠道口径不一）。
- 查询失败显示「额度查询失败」，不把未知显示成 0。

### 交互铁律：**正文信息不得只靠 hover 才能看到**

- **正文信息**（卡片 / 列表里的数据与说明）必须**直接可见**（写进正文，允许换行、不裁切），
  或放进**点击后**才出现的详情区（弹窗 / 抽屉 / 展开行）—— 截图、投屏、触屏与键盘操作都
  拿不到 hover 内容，关键信息不能依赖悬停。
- **原生 `title=` 属性仍然禁用**（浏览器原生 tooltip 样式不可控、无障碍差）；
  按钮的无障碍名称用 `aria-label`（不产生可见气泡）。
- **例外：图表数据详情用自绘 hover 浮层**（2026-10-30 放宽）—— 数据点密度高、
  点击不合适，用 `components/usage/ChartTooltip.tsx`（跟随鼠标、portal 到 body、
  `pointer-events-none` 不挡鼠标），形态对齐 ZCode 的「使用统计」；热力图 / 环形 / 趋势图
  三块的浮层即此实现。新增悬停交互先确认属于「图表数据详情」这一类。
- 图表的 hover 浮层里**不承载独占信息**：同样的数值必须在浮层之外也有出处（图例、
  KPI、详情区），浮层只是「指着看」的快捷方式。

这条只管**信息**，不管**低频动作按钮**：账号行上的切换 / 删除默认 `opacity-0`、
`group-hover` 才出现（`group-focus-within` 保键盘可达，`pointer-coarse` 触屏常显）。
信息一个都不能藏，动作可以 —— 动作藏了只是少一条捷径，信息藏了等于没有。

### 登录链接：**复制，不弹新窗口**

「添加账号」弹窗里的授权链接，点击只做**复制到剪贴板**（剪贴板不可用时静默失败，
用户仍可手动复制下方那一行），**不调 `window.open`、不用 `target="_blank"`** ——
由用户自己决定在哪个浏览器 / 窗口打开。页面里不应出现「点授权链接 → 自动开新标签页」。

「添加账号」是**强制重新授权**（后端 `force`），但**不会先删掉现有凭据**：
授权要等人操作，期间旧凭据继续可用；只有新凭据落盘（原子覆盖）才替换它。
（旧实现先删凭据，授权没走完渠道就掉线，界面出现「未登录 + 账号生效中」的矛盾状态。）

### 不可逆操作：**二次确认**

删除账号（`onRemove`）不可逆（**生效账号会同时登出**），必须先确认：点垃圾桶弹出
`ConfirmDialog`（标题「删除账号」+ 渠道 / 账号名 + 「取消 / 删除账号」），只有点
「删除账号」才真调 `onRemove`。规则：

- 弹窗**挂到 `document.body`**（`createPortal`）：账号卡带 `@container`，它隐含
  `contain: layout`，会成为 `fixed` 后代的包含块，不 portal 就会被卡片裁切；
- 同一时刻只允许一个账号处于待确认态；
- 切换账号、开始删除（`busyKey !== null`）时清空确认态；
- 点遮罩 / 按 ESC / 点「取消」都是取消，不产生任何副作用；默认焦点在「取消」上。

### 账号状态恢复：全靠自动路径，不设手动解除入口

异常（`error`，连败熔断）与冷却（`cooldown`，额度耗尽）都能**自愈**：熔断到期自动半开试探、
冷却到期惰性恢复、请求成功清零连败，三条路径都在请求路径上自动完成，不需要用户干预
（语义见 [POOL-ARCHITECTURE.md](./POOL-ARCHITECTURE.md) §2.4「额度耗尽 → 账号冷却」与「熔断自动恢复」）。因此账号行上
**不提供手动「解除」按钮**。

- 后端 `resetAccount` 命令仍在（`/web/api/commands` 仍接受，等价 `clearAccountState`），
  但控制台**不设入口**：自动恢复已覆盖全部可恢复情形，多一个按钮只会多一处可误解的操作。
- 唯一不可自动恢复的是 `unauthorized`（凭据本身失效）—— 它本来就不许解除，只能重新登录；
  界面如实显示状态并引导走「重新授权」。

## 技术栈与构建

- React 19 + TypeScript + Vite 8（`base=/web/`）+ Tailwind CSS v4 + TanStack Query v5 +
  react-router v8 + lucide-react 图标 + **Radix UI（headless 原语）**。
- **Radix 用在哪**（2026-10-26 引入）：`@radix-ui/react-toast`（轻提示）、
  `@radix-ui/react-dialog`（登录弹窗）、`@radix-ui/react-alert-dialog`（删除确认）。
  选它的理由是 **headless** —— 只给行为（焦点陷阱、焦点归还、滚动锁、aria 接线），
  不给视觉，所以控制台的 Codex 近黑单色风格完全由 Tailwind 令牌决定，没被组件库带跑。
  （antd / MUI 自带一整套设计系统，引进来要么覆盖它、要么推翻现有设计。）
- **`packages/ui` 不受依赖白名单约束**：`scripts/verify-contract.mjs` 的 `DEP_ALLOW`
  只管渠道包与 `packages/cli`；UI 包本来就有 15 个第三方包（含 devDependencies：React / Tailwind /
  Vite / TanStack Query / react-router / Radix UI / lucide / react-markdown 等）。
- `npm run build` 顺序：`tsc -b` → `vite build packages/ui` → cli bundle →
  `scripts/copy-ui.mjs` 把产物拷到 `packages/core/gateway/dist/ui` 与 `packages/cli/dist/ui`
  （**少拷一份，全局 `mx web` 就报「UI 未构建」**）。

### 静态资源落点：必须走 `src/assets/`，不要放 `public/`

页面图标在 `packages/ui/src/assets/favicon.svg`，由 `index.html` 以 `/src/assets/favicon.svg`
引用。Vite 会把它打进 `assets/` 并加内容哈希（产物形如 `/web/assets/favicon-<hash>.svg`）。

**为什么不能放 `public/`**：console handler 只托管两个静态位置 —— 前缀根 `/web/`（返回
`index.html`）与 `/web/assets/*`；其余 GET 一律走 SPA 回退（`console.ts` 的
`serveStatic(res, WEB_UI_INDEX)`）。放 `public/` 的 `/web/favicon.svg` 会被回退成 HTML
而拿不到 SVG。同理，图标不要声明成 `/web/favicon.svg` 这类前缀根路径。

在 `index.html` 里显式声明 `<link rel="icon" type="image/svg+xml" href="/src/assets/favicon.svg">`
还有第二个作用：浏览器不再去要默认的 `/favicon.ico` —— 那个路径在网关根下不存在，
会以 `not_found` 写进 `access/<date>/failure.log`，属纯噪音。

## 数据通道

- `GET /web/api/state`：登录快照（ui_state / message / auth_url / qr_url / **login_input** / 端点），
  外加模型池视图所需的 `models` / `model_info` / `channel_caps`（各渠道能力位）。
  - `login_input` 非空 = 渠道在等用户输入（两步登录，如 loomy 的短信验证码）。
    界面据此把登录弹窗切成**输入卡**；`null` = 没有待回答的输入。
  - **`model_info` 走进程内缓存**（跨渠道索引 `buildCrossModelIndex`，30 秒 TTL +
    目录变化/池集合变化时显式失效）：建一次要枚举全部渠道目录 × 每模型查规格，实测约 400ms
    且**同步阻塞** —— 控制台 3 秒轮一次，不缓存就会把事件循环占住约 15%，同页面的
    accounts / logs 请求全在排队（症状：进入账号池要等很久）。缓存命中后 `/api/state`
    稳定在几十毫秒。
- 前端对所有轮询查询用 **`staleTime` = 轮询间隔** + `placeholderData: (prev) => prev`：
  间隔内再进页面**直接用缓存**（不发网络请求，也不清空成骨架）；首访没有旧数据时仍走骨架。
  轮询间隔见各页：state 3s、overview 5s、logs 5s、accounts 15s / logins 10s / billing 60s、
  模型健康度 60s。
- `POST /web/api/commands`：动作分发（login / status / **models** / billing / accounts /
  activateAccount / **resetAccount** / removeAccount / syncPool / pasteCallback /
  **submitInput** / **cancelInput**）。
  - `billing` 支持 `args.refresh: true`（真实重查各渠道账单）与 `cid` 过滤（单渠道刷新）。
    账单行以**渠道**为主维度：上游目录里没有 deepseek 家族模型的渠道（如 workbuddyai 的
    `hy3`）进不了统一模型池，但只要 `capabilities.billing` 且账本有它的条目，
    就会补一行（否则这类渠道在账号池页的额度恒为 0 —— 2026-11-06 实测修复）。
  - `resetAccount`：解除 `error` / `cooldown` 标记（不动凭证）；`unauthorized` 会被拒绝并给出原因。
    后端保留的命令调用面，UI 已无入口（账号状态靠自动恢复，见上文「账号状态恢复」）。
  - `pasteCallback`：手工兜底通道，把用户粘回的回调链接喂给等待中的登录流程。
    raccoon 等授权码渠道现在优先走**本地 HTTP 回调自动完成**，Web UI 已不提供粘贴入口
    （控制台与网关同机，回调必然到得了本机端口）；该动作保留给 CLI 与非本机场景。
  - `submitInput`：把两步登录的输入交回给等待中的渠道；`cancelInput`：弹窗关闭时调用，
    让等待输入的渠道立刻收尾（不调用会挂到 10 分钟超时）。
- `GET /web/api/logs`：访问日志查询（只读）。参数 `date` / `outcome` / `cid` / `model` /
  `stream` / `slow` / `q` / `limit`（上限 500，默认 100）/ `offset`。
  返回实际日期（当天无日志时后端回落到最新日期）、可选日期与渠道、`stats`（基于**未过滤**读窗口的
  当天概览）、`total`（命中筛选数）、`entries`。
  - 读窗口有界：每个 outcome 文件只读尾部 1MB、总扫描 2 万行；超出时 `truncated=true`，
    界面据此把统计标注成「只覆盖最近 N 条」，而不是假装是全量。
  - 只读 `success` / `failure` / `other` 三个分桶 —— `slow.log` 是它们的并行副本，
    一起读会让慢请求在列表里出现两遍。
  - **固定只看模型请求**（`path === "/v1/chat/completions"`）：`/health` 等非模型请求同样落盘，
    但不进这个列表（路径常量是 `runtime/log-store.ts` 的 `MODEL_REQUEST_PATH`）。
- `GET /web/api/usage`：用量统计聚合（只读）。参数 `range`（`today` / `7d` / `30d` / `90d` / `365d` / `all`，默认 30d；`365d` 只供热力图，`all` = 累计）。
  服务端逐日全量扫描 access 日志（不走日志页的读窗口上限），已过去的日期带进程内缓存；
  口径与指标公式见 [USAGE-STATS.md](./USAGE-STATS.md)。
- `GET /web/api/logs/payload`：按 `id`（+ 可选 `date`）读回请求正文抓取记录，
  返回 `records`（`phase=client` 的客户端原样体 + `phase=upstream` 的各次上行体）。
  恒开启：正文抓取不可关闭（见 [LOGGING.md](./LOGGING.md) §9）。
- 这几个只读端点**带同源校验**（与 `POST /api/commands` 同款）：日志与用量含模型名与渠道，
  比 `/api/state` 更不该被跨源页面读到；无 `Origin` 头时放行，curl / 脚本不受影响。
- `POST /web/api/theme`：切主题；`POST /web/api/retry-login`：重试登录。
  两者在 `console.ts` 里已实现，但当前 UI **没有入口**（深色是唯一主题，也没有重试登录按钮）——
  前端 `lib/api.ts` 里的 `setTheme` / `retryLogin` 只是保留的调用面。
- `GET /web/api/overview`：仪表盘聚合视图（一次拉全）。返回当日 KPI
  （`usage`：请求/成功/失败/慢/平均耗时/tokens）、每渠道状态（`channels`：模型数 +
  账号健康分布 + 今日成败）、模型池概览（`model_pool`：总数/免费/多模态/思考）、
  最近 5 条请求（`recent`：时间 / **渠道** / 模型 / 结果 / 耗时 / tokens / TPS；渠道列窄屏（< 768px）让位
  —— 390px 下 tokens 与 TPS 是主信息；失败与中断额外带
  `error` + `message`，界面把状态码与原因直接摊在同一行、超长截断）。带同源校验，5 秒轮询。
- `POST /web/api/translate`：把一批文本译成中文（请求上下文的「翻译」按钮用）。
  网关代发到公开翻译端点，契约、错误码与上游字数边界见 [TRANSLATION.md](./TRANSLATION.md)。
  带同源校验（正文会离开本机，按写操作对待）。
- `/api/commands` 返回值由前端 `lib/api.ts` 统一**解包 `data`** —— 页面不要再取一层
  `.data`（双重解包会导致 tab 崩溃）。

## 账本维度

账本主维度是**渠道**（used / 冷却 / billing_at），另按**生效账号**拆分 ok / fail 计数
（`ChannelLedger.accounts[key]`），控制台账号池卡片按「渠道 × 账号」展示；
账本数字记在请求发生时的当前生效账号头上。

## 演示模式（在线演示 + 本地静态构建）

控制台的**演示构建**（`DEMO=1`）用一份**虚构数据**在浏览器里跑完整交互流程，
不需要起网关、不碰任何真实账号。

> **在线演示：<https://bluechonk.github.io/modelmux/>**（GitHub Pages，只发布演示构建）。
> 真实控制台仍是**本机工具**（要读本机网关与账号池），不上公网 —— 看真机就 `mx web` ✓。

### 发布（GitHub Pages）

`.github/workflows/demo-pages.yml`：push 到 `main`（命中 `packages/ui/**` / 依赖清单 /
workflow 自身）或手动 `workflow_dispatch` 时，`npm ci` → 构建演示包 → 部署到 Pages。

两个**必须**记住的点（改 workflow 或 `vite.config.ts` 前先读）：

| 点 | 为什么 |
| --- | --- |
| `DEMO_BASE=/<repo>/` | Pages 的**项目站点**挂在 `https://<owner>.github.io/<repo>/` 下。资源若用根路径 `/assets/…` 会 404、整页空白。构建时把前缀传给 `vite.config.ts`，`base` 与 `App.tsx` 的 `basename` 都从 `__DEMO_BASE__` 推导（两处各写一份必然漂移）。用户站点（`<owner>.github.io`）前缀是 `/`，workflow 里按仓库名判断。 |
| `cp dist/index.html dist/404.html` | 纯静态托管没有 SPA 回退：直接访问 `/accounts` 会 404。Pages 用 `404.html` 兜底，客户端路由再把页面画出来（**状态码仍是 404，但页面正常渲染**；入口 `/` 是 200）。 |

Pages 的源设为 **GitHub Actions**（`build_type: workflow`），不是 gh-pages 分支 ——
产物由 `upload-pages-artifact` 直接交给 Pages，仓库里不留构建产物。

### 为什么需要「演示构建」

真实控制台每个页面都要 `fetch('/web/api/*')` 读本机网关；演示构建把这层换成内存实现，
于是**任何静态托管**（甚至直接双击 `dist/index.html`）都能看界面与点流程 ✓。

### 实现

| 位置 | 作用 |
| --- | --- |
| `src/lib/demo.ts` | 虚构数据源 + 内存状态机（渠道/模型/账号池/账本 + 登录流程） |
| `src/lib/api.ts` | `IS_DEMO` 为真时用内存实现替换所有 fetch |
| `vite.config.ts` | `DEMO=1` 时切换 base（`DEMO_BASE`）并注入 `__DEMO_MODE__` / `__DEMO_BASE__` |
| `src/App.tsx` | `basename` 从同一个 `__DEMO_BASE__` 推导 |
| `src/env.d.ts` | 两个注入常量的类型声明 |

构建：`DEMO=1 npm run build --workspace=packages/ui`（本地预览，`base=/`），
产物在 `packages/ui/dist/`，直接用静态服务器打开即可；
发布到 Pages 时加 `DEMO_BASE=/modelmux/`（见上表）。

演示的是**交互流程**而非假死截图：添加账号真的会把渠道置为已登录、账号入池并设为生效，
模型区与统计卡随之更新（登录/登出一个渠道会同时改变模型数与渠道数）。

### 数据纪律

演示数据里所有 uid / 手机号 / 域名一律用明显虚构的占位值
（`demo000000000000a1`、`13800138000`、`example.com`），
**不读取也不复制 `~/.modelmux/` 下的任何真实数据** ✓。
（`13800138000` 是虚构号段，不是打码 —— 演示数据要贴合「显示原样」的口径。）
侧栏常驻「演示模式：数据均为虚构，未连接任何真实网关」提示 ✓。

**仓库不放控制台截图**（`docs/images/` 已删除）：界面与文案改得快，图必然过时；
更关键的是真实控制台的账号页会显示本机账号的 uid / 昵称 / 额度，拍进仓库就是泄漏
（旧截图曾把真实 UID 与账号 id 拍进去过）。要看界面形态就用**在线演示**
（<https://bluechonk.github.io/modelmux/>）或本机 `mx web`；需要自己重拍时的命令见本节
「本地预览」，浏览器视口用 **1440×900**。

### 本地预览

演示构建的失败模式（base 前缀不对 → 整页空白）只有看到真实产物才暴露，
所以改完 UI 先本地构建看一眼：

```bash
DEMO=1 npm run build --workspace=packages/ui   # 产物在 packages/ui/dist/
npx serve packages/ui/dist                      # 或任何静态服务器，打开首页即可
```

真实控制台不需要这些：`mx web` 直接起在 `http://127.0.0.1:4412/web/` ✓。
